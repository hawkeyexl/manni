**Outcome.** An agent that answers from the docs, or edits them, reads each passage with its proof. It knows which sentences are verified before it quotes them.

**Steps.** Devin builds the graph and exports the chunk artifact on the checkout the agent reads. The MCP SDK comes with manni. He registers `manni graph serve` in the client's MCP config. In Claude Code the `manni` plugin from M24 does those steps for him. Its server publishes when the artifact is missing or stale, and again after the checkout changes. The agent calls `lookup` with one question and gets three complete sections: the ranked matches, what they link to, and what depends on them. Each passage carries its pins, dates and eval verdicts. He sets `--withhold drifted` so no agent call serves a passage whose pin broke, and no tool argument can lower that floor. A refusal comes back as an answer with a reason, never as an error.

**What success looks like.** The agent quotes current sentences, flags drifted ones, and names the pages a change affects. Related journeys are D13 (publishing the graph) and M24 (an agent that reads the docs while writing them).
