**Outcome.** Several docs sets serve the same readers, and "Maya" is one record that every repository reads. Each repository's `manni strategy check` reports only what that repository can fix. Coverage across products is one `jq` over JSON each repository already prints.

**Steps.** Sara's trigger is a second repository that kept its own copies of the records, so its Maya drifted from this one. She checks out the repository that owns the records beside the one that borrows them. In the borrowing repository's `manni.config.yaml`, the `strategy` collection names the owner's `audiences/`, `personas/` and `journeys/` folders as directories, so a missing checkout stops the run. A record read from outside the config file's directory is borrowed. Its values resolve every page's references, and `check` files no finding in it. The summary counts the borrowed records, as `(N borrowed)` and `summary.borrowed`. A kept copy draws `duplicate-id`, and the fix says to remove it. She removes the copies and keeps the journeys only her product serves, which `check` still holds to its pages. In CI, a second `actions/checkout` puts the owner beside the repository, pinned with `ref:`. She runs `manni strategy list -f json` in each repository and joins the files by id with `jq`.

**What success looks like.** One Maya, read by every repository. A typo on a borrowing page fails there, and nothing annotates the owner's files. Related journeys are S17 (the records and the check) and D16 (the one-command gate).
