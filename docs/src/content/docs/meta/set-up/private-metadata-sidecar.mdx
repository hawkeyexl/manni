title: Keep private metadata in a sidecar
description: "Validate public docs against keys a sidecar manifest supplies, read from a private checkout or fetched by URL from another repository, public or private."
---

import { Steps, Aside, LinkCard, CardGrid } from '@astrojs/starlight/components';

Your docs repository is public. Some of the metadata its pages must carry is
not. Examples are the internal design note a guide was written from, the ticket
that tracks it, and the team that owns it. In the public frontmatter it leaks. In a private
spreadsheet it is never validated, and the whole point of a `jira:` key is that
CI refuses a page without one.

A **sidecar** puts the value in a private repository and keeps the contract with
the page. A YAML manifest supplies a fixed set of keys for named documents, and
`manni meta` merges them into each page's metadata before resolving its schema.
The public repository never holds the value, and the private CI run validates
the public pages against a schema that requires it.

By the end you will have two repositories, one manifest, and a private CI job.
The job fails when a public page has no ticket or a ticket is misspelled. It
also fails when someone writes the ticket into the public page by hand.

The manifest need not sit beside the config, and it need not be private.
`file:` also takes an `https://` URL, fetched every run. One public repository
can supply keys for another's pages that way, with no secret anywhere.
[Fetch the manifest by URL](#fetch-the-manifest-by-url) covers both cases.

<Aside type="note" title="What this page covers">
The journey. The contract, meaning every rule, message and exit code, lives in
the [configuration reference](/manni/meta/reference/configuration/#sidecars).
</Aside>

## The layout

The private repository owns the config, the manifest, and the private schema.
The public repository is a git submodule inside it:

```
private-repo/
  manni.config.yaml     # paths, sidecars, overrides
  docs-meta.yaml        # the manifest
  schemas/private.json  # requires the private keys
  public/               # git submodule: the public docs repository
    manni.config.yaml   # plain; never mentions a sidecar
    docs/guides/auth.md
```

Two sibling checkouts also run, and report worse. SARIF locates every finding
relative to the nearest repository root and cannot represent a finding in
another repository's file. From a sibling layout every document finding is
therefore dropped from the log. The submodule keeps every document under the private
root. The reasons are in the
[reference](/manni/meta/reference/configuration/#the-recommended-layout).

## Set it up

<Steps>

1. **Add the public repository as a submodule.** From the private repository:

   ```sh
   git submodule add https://github.com/your-org/public-docs public
   ```

2. **Write the manifest.** One entry per page, keyed by the page's path
   relative to the config file. Paths are exact. There are no globs.

   ```yaml title="docs-meta.yaml"
   public/docs/guides/auth.md:
     source: internal/auth-design.md
     jira: PLAT-412
   public/docs/guides/billing.md:
     source: internal/billing.md
     jira: PLAT-388
   ```

3. **Write the private schema.** It requires the keys the manifest supplies.
   Leave `additionalProperties` unset, or the public keys fail it.

   ```json title="schemas/private.json"
   {
     "type": "object",
     "required": ["title", "jira"],
     "properties": {
       "title": { "type": "string" },
       "source": { "type": "string" },
       "jira": { "type": "string", "pattern": "^PLAT-[0-9]+$" }
     }
   }
   ```

4. **Declare the sidecar in the private config.** `keys:` names what the
   manifest owns. A document carrying one of those keys itself is a finding,
   and an entry setting any other key is an error.

   ```yaml title="manni.config.yaml"
   meta:
     paths: ["public/docs/**/*.md"]
     sidecars:
       - file: ./docs-meta.yaml
         keys: [source, jira]
     overrides:
       - files: "public/docs/**/*.md"
         schemas: [./schemas/private.json]
   ```

   The public repository's own `manni.config.yaml` stays as it is. It never
   mentions a sidecar, so no public run warns about a private file it cannot
   see.

5. **Run it from the private checkout.** A bare `manni meta validate` uses the
   config's `paths:`, which is what makes the orphan check run.

   ```sh
   npx -y @hawkeyexl/manni meta validate
   ```

</Steps>

## What a failure looks like

`test/fixtures/sidecars/` is the corpus this feature's tests run. One page
has a malformed ticket in the manifest, one has no entry, and one carries
`jira:` in its own frontmatter:

```
✓ docs/auth.md
✗ docs/billing.md
    /jira  must match pattern "^PLAT-[0-9]+$"  (docs-meta.yaml:6)  [./private.schema.json]
✗ docs/new.md
    (root)  must have required property 'jira'  (line 1)  [./private.schema.json]
✗ docs/ops.md
    /jira  "jira" is owned by sidecar docs-meta.yaml; remove it from the document  (line 3)  [sidecar:owned]

4 files checked, 1 passed, 3 failed, 3 errors
```

Each line points at the place to fix. `billing.md`'s bad value is at
`docs-meta.yaml:6`, so the manifest is what to edit. `new.md` needs an entry.
`ops.md` needs its `jira:` line removed, because the manifest is the only place
that key may be set. All three are exit 1, and `--format github` annotates the
manifest line for the first and the page line for the other two.

A renamed page whose entry was not updated is different. On a config-corpus run
it is exit 2. An entry naming a page the run did not load is a named input
that is not there. The same fixture directory carries a second config
whose manifest names a page that is gone:

```
$ manni meta validate -c manni.orphan.config.yaml
manni: Sidecar manifest docs-meta.orphan.yaml:3 names "docs/gone.md", which this run did not load. Fix the entry, or remove it.
```

## The two workflows

The public repository keeps its ordinary gate. Nothing about sidecars reaches
it:

```yaml title="public-docs/.github/workflows/manni.yml"
name: Validate metadata
on: [push, pull_request]
jobs:
  manni:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: hawkeyexl/manni@v0
```

The private repository checks out its submodule and runs from its own root.
`submodules: true` is what brings the public pages in. If the public repository
is public, the default token can clone it. If it is only public to your
organization, pass a token that can read it:

```yaml title="private-repo/.github/workflows/manni.yml"
name: Validate metadata
on: [push, pull_request]
jobs:
  manni:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          submodules: true
          token: ${{ secrets.PUBLIC_DOCS_READ_TOKEN }}
      - uses: hawkeyexl/manni@v0
```

The Action passes no paths, so `paths:` comes from the private config and the
orphan check runs. Bump the submodule pointer when the public docs change, or
the private run validates the pages as they were.

## Fetch the manifest by URL

`file:` accepts an `https://` URL as well as a path. The manifest is fetched at
the start of every run, never cached, and merged exactly as a local one is.
Use it when the run cannot check the manifest out. Two cases are common, and
the public one comes first because it needs nothing else.

### Across public repositories

Nothing here is private. One public repository keeps a catalog, say which team
owns each page, and another public repository's pages are judged by it. The
docs run never clones the catalog. A plain URL, and no token anywhere:

```yaml title="docs-site/manni.config.yaml"
meta:
  paths: ["docs/**/*.md"]
  sidecars:
    - file: https://raw.githubusercontent.com/your-org/docs-catalog/main/owners.yaml
      keys: [team, owner]
  overrides:
    - files: "docs/**/*.md"
      schemas: [./schemas/owned.json]
```

The ordinary public workflow runs it unchanged. There is no secret to pass,
and the public log shows only public values. A finding on a fetched value
names the URL and the manifest line, so the catalog is what to edit.

### A private manifest

The private manifest lives in a repository the job does not check out, such as
a platform team's catalog that serves several docsets. The run still starts
from a private checkout, with the public pages as its submodule. Only the
manifest moves. Add `tokenEnv`, the name of an environment variable holding a
bearer token:

```yaml title="private-repo/manni.config.yaml"
meta:
  paths: ["public/docs/**/*.md"]
  sidecars:
    - file: https://raw.githubusercontent.com/your-org/docs-catalog/main/docs-meta.yaml
      keys: [source, jira]
      tokenEnv: PRIVATE_DOCS_TOKEN
  overrides:
    - files: "public/docs/**/*.md"
      schemas: [./schemas/private.json]
```

The workflow passes the secret as that variable. The token never appears in
the config, a message, or a report:

```yaml title="private-repo/.github/workflows/manni.yml"
name: Validate metadata
on: [push, pull_request]
jobs:
  manni:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          submodules: true
          token: ${{ secrets.PUBLIC_DOCS_READ_TOKEN }}
      - uses: hawkeyexl/manni@v0
        env:
          PRIVATE_DOCS_TOKEN: ${{ secrets.PRIVATE_DOCS_TOKEN }}
```

Both hosts accept a bearer token on their raw-file route, so the same
`tokenEnv` serves either:

```text
GitHub  https://raw.githubusercontent.com/OWNER/REPO/REF/PATH
GitLab  https://gitlab.com/api/v4/projects/ID/repository/files/PATH/raw?ref=REF
```

| Host | Token |
|---|---|
| GitHub | A fine-grained personal access token with read access to the repository's contents. |
| GitLab | A project or personal access token with the `read_repository` scope. `PATH` is URL-encoded, so `docs/docs-meta.yaml` is written `docs%2Fdocs-meta.yaml`. |

<Aside type="caution" title="Fetch from the private side">
A public repository's CI logs are public. A private manifest fetched into a
public run puts its values in that log. Use the URL form from the private side,
when the private run cannot check the manifest out, or across public
repositories. Never use it to feed a public run with private values.
</Aside>

A run that cannot reach the manifest stops before any page is judged, and says
why. The status is named and the token never is:

```
$ PRIVATE_DOCS_TOKEN= manni meta validate
manni: Sidecar manifest https://raw.githubusercontent.com/your-org/docs-catalog/main/docs-meta.yaml: the environment variable PRIVATE_DOCS_TOKEN named by "tokenEnv" is not set.
                                                                                    exit 2
$ manni meta validate --offline
manni: Sidecar manifest https://raw.githubusercontent.com/your-org/docs-catalog/main/docs-meta.yaml is remote and the run is offline. Vendor it to a path, or drop --offline.
                                                                                    exit 2
```

Every rule, including the timeout, the body cap, the redirect behaviour and
`http://`, is in the
[reference](/manni/meta/reference/configuration/#remote-manifests).

## Editing the values

The first increment is read-only. A key the manifest owns is readable by every
command and writable by none:

Again over the fixture corpus:

```
$ manni meta get jira docs/auth.md
docs/auth.md: jira=PLAT-412

$ manni meta query "UPDATE docs SET jira = 'PLAT-1' WHERE _path = 'docs/auth.md'"
manni: "docs/auth.md": "jira" is owned by sidecar docs-meta.yaml; edit the sidecar file instead.
```

`fill` refuses a page whose missing key the manifest owns, for the same reason.
Edit `docs-meta.yaml` by hand. A corpus check in the private config can still
see every private key. So "every guide has a ticket in the open state" is a
[SQL rule](/manni/meta/ci/query-gates/) like any other.
