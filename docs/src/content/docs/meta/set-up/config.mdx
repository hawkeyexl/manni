A `manni.config.yaml` stores what "valid" means for your repo: which files to check, which to skip, and which schema set they must satisfy. With it committed at your repo root, both you and CI can run a bare `manni meta validate` and get a consistent, repeatable result.

Every key is optional. This page covers where manni meta looks for the file, then each key in turn. It then gives a complete worked example, and shows how command-line flags combine with what you configure.

## Where manni meta looks for the config

`manni.config.yaml` is one file shared by every tool under `manni`. Each tool owns one top-level key, and the metadata tool's is `meta:`. Everything this page describes goes under it:

```yaml title="manni.config.yaml"
meta:
  paths:
    - "docs/**/*.md"
  schemas:
    - google:okf:0.1
```

manni meta finds your config in one of two ways:

- **Discovery.** With no `--config` flag, manni meta looks in the current working directory for `manni.config.yaml`, then `manni.config.yml`, and then repeats that in each parent directory. The first file with a `meta:` key wins, and the search stops at your repo root. That is the first directory containing `.git`. If no parent is a repository, only the current directory is checked.
- **Explicit path.** Pass `-c <path>` (or `--config <path>`) to point at a specific file. If that file does not exist, manni meta exits with an error rather than falling back to discovery.

Two older file names are still read, each with a warning on stderr: `moose.config.yaml`, the family file under its previous name, and `docmeta.config.yaml`, whose whole document is the `meta:` section with no wrapper key. Rename the file and indent its keys under `meta:` to silence the warning. The [configuration reference](/manni/meta/reference/configuration/#discovery) has the full order.

Because the search walks up, `manni meta validate` gives the same verdict from your repo root as it does from `docs/` or from a package subdirectory. When a config governs a run, manni meta prints a line naming it, such as `Using manni.config.yaml (../..)`. To run against the built-in defaults instead, pass `--no-config`.

<Aside type="note">
Relative paths written **in** the config resolve against the config file's own directory, not the directory you ran from. That covers `paths`, `exclude`, and any local `.json` schema file. Paths you type on the command line stay relative to where you are. See the [configuration reference](/manni/meta/reference/configuration/#what-relative-paths-are-relative-to).
</Aside>

## The keys

### `paths`

A list of files, directories, or globs to validate. This is the **fallback** manni meta uses when you do not pass any positional paths on the command line.

```yaml title="manni.config.yaml"
meta:
  paths:
    - "docs/**/*.md"
    - "articles/**/*.md"
```

With this in place, a bare `manni meta validate` checks everything under `docs/` and `articles/`. Pass paths explicitly and they take priority, so `manni meta validate README.md` validates only `README.md`, ignoring `paths`.

<Aside type="caution">
You might provide no positional paths, with `paths` empty or absent, and no config found. Then manni meta exits with code `2` and the message `No files to validate.` This is an operational error, and manni meta will not silently do nothing.
</Aside>

### `exclude`

A list of globs to skip. Your excludes are **merged with** manni meta's built-in defaults, and with any `--exclude` flags passed on the command line. They add to the exclusion set rather than replacing it.

```yaml title="manni.config.yaml"
meta:
  exclude:
    - "**/drafts/**"
```

manni meta always ignores `**/node_modules/**` and `**/.git/**`, so you never need to list those. The example above additionally skips any `drafts` folder.

<Aside type="note" title="How excludes combine">
The final exclusion set is the built-in defaults (`**/node_modules/**`, `**/.git/**`) plus your config `exclude` plus any `--exclude` flags. There is no way to remove the built-in defaults.
</Aside>

### `schemas`

The default schema **set** applied to every matched file. Each file must satisfy **all** schemas in the list: they are validated against the set, not against the first match.

```yaml title="manni.config.yaml"
meta:
  schemas:
    - google:okf:0.1
```

A schema reference can be one of three kinds:

- A **built-in id** in `vendor:name:version` form, such as `google:okf:0.1`.
- A **local file path** to a `.json` schema, such as `./schemas/article.json`.
- An **`http(s)` URL** to a remotely hosted schema.

If you omit `schemas` entirely, manni meta falls back to the built-in [`google:okf:0.1`](/manni/meta/schemas/) schema, which requires a `type` field.

### `overrides`

A list of per-glob rules that assign a different schema set to a subset of files. Each entry has a `files` glob and a `schemas` list. The first override whose glob matches a file wins, and its schema set replaces the default `schemas` for that file.

```yaml title="manni.config.yaml"
meta:
  overrides:
    - files: "api/**/*.md"
      schemas:
        - google:okf:0.1
        - ./schemas/api-reference.json
```

Overrides are how you require stricter metadata for one area of the repo without affecting the rest. They are not the last word, though: a file's own `$schema` field and the CLI `--schema` flag both take precedence over them. The dedicated overrides guide walks through the full resolution order.

## A complete example

This config validates Markdown under `docs/` and `articles/`, skips drafts, applies the OKF schema everywhere by default, and layers an extra schema onto `articles/`.

```yaml title="manni.config.yaml"
meta:
  # Default targets when no paths are passed on the command line.
  paths:
    - "docs/**/*.md"
    - "articles/**/*.md"

  # Paths to skip (node_modules and .git are always excluded).
  exclude:
    - "**/drafts/**"

  # The schema set every matched file must satisfy by default.
  schemas:
    - google:okf:0.1

  # Per-glob overrides (first match wins).
  overrides:
    - files: "articles/**/*.md"
      schemas:
        - google:okf:0.1
        - ./schemas/article.json
```

Run it from your repo root:

```bash
npx manni meta validate
```

## How CLI flags combine with the config

Some command-line flags layer onto the config; others replace it. Keep the distinction in mind when you run manni meta locally with extra flags:

| Flag | Effect relative to config |
|---|---|
| positional `[paths...]` | **Replaces** `paths` for this run. |
| `--exclude <glob>` | **Merges** with config `exclude` and the built-in defaults. |
| `-s, --schema <ref>` | **Overrides** all schema resolution. Config `schemas`, `overrides`, and file `$schema` are ignored. |

<Aside type="tip">
For the full flag list, see the [CLI reference](/manni/meta/reference/). For the complete schema-resolution precedence chain, see the [Schema resolution reference](/manni/meta/reference/schema-resolution/).
</Aside>
