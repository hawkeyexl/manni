{/* cite okf-anchors-the-default-set */}
**`google:okf:0.1`** is the Open Knowledge Format (OKF) v0.1 frontmatter schema
shipped with manni meta. It is the first member of the [default
set](/manni/meta/reference/schema-resolution/#precedence). When no `--schema`, file
`$schema`, or config rule applies, manni meta validates against `google:okf:0.1`.
It pairs that with
[`passo-uno:seven-action:1.0`](/manni/meta/reference/taxonomy-schemas/), which
constrains an optional `action` field and adds no requirements of its own. The
eleven [manni vocabularies](/manni/meta/reference/manni-vocabularies/) follow,
and `manni:core:1.0.0` among them requires `title` and `description`. For
every other schema manni meta ships, see the [built-in schema
registry](/manni/meta/reference/built-in-schemas/).

| Property | Value |
|---|---|
| Id | `google:okf:0.1` |
| Title | Open Knowledge Format (OKF) v0.1 |
| Dialect | [Draft 2020-12](/manni/meta/reference/schema-resolution/#dialects) |
| Additional properties | Allowed (`additionalProperties: true`) |
| Reference kind | [builtin](/manni/meta/reference/schema-resolution/#reference-kinds) |
| JSON | [`schemas/okf/0.1.json`](/manni/schemas/okf/0.1.json) |

{/* cite okf-published-url-resolves-to-the-bundle */}
The JSON above is the schema itself, served at a
[permanent, version-pinned URL](/manni/meta/reference/built-in-schemas/#the-published-urls).
Read it, `$ref` it from a schema of your own, or hand it to a JSON Schema tool
that is not manni meta. Naming that URL inside manni meta costs no network call: it
resolves to the same bundled copy `google:okf:0.1` does.

{/* cite okf-requires-only-type */}
OKF requires only `type`. Every other field is recommended, and unknown keys are
explicitly tolerated, so a file may carry extra metadata without failing.

## Fields

| Field | Type | Format | Constraint | Status |
|---|---|---|---|---|
| `type` | string | n/a | `minLength: 1` | **Required** |
| `title` | string | n/a | n/a | Recommended |
| `description` | string | n/a | n/a | Recommended |
| `resource` | string | `uri` | n/a | Recommended |
| `tags` | array of string | n/a | n/a | Recommended |
| `timestamp` | string | `date-time` | n/a | Recommended |

- **`type`**: a short string identifying the kind of concept; used for routing,
  filtering, and presentation. Must be a non-empty string.
- **`title`**: human-readable display name. When omitted, consumers may derive
  a title from the filename.
- **`description`**: single-sentence summary used for indexing and previews.
- **`resource`**: a URI uniquely identifying the underlying asset. Absent for
  abstract concepts.
- **`tags`**: short strings for categorization.
- **`timestamp`**: ISO 8601 date-time of the last meaningful change.

<Aside type="note">
Under this schema, only a missing `type` fails a file. The recommended fields are validated
for **format** when present. A `resource` that is not a valid URI, or a
`timestamp` that is not a valid date-time, fails, but their absence does not.
</Aside>

## Example

{/* cite okf-minimal-file-needs-only-type */}
A minimal file that passes against `google:okf:0.1`:

```md
---
type: concept
---
```

A fuller file using the recommended fields:

```md
---
type: concept
title: Schema resolution
description: How manni meta picks a schema set for each file.
resource: https://example.com/docs/schema-resolution
tags: [reference, schemas]
timestamp: 2026-06-25T12:00:00Z
---
```

## Specification

`google:okf:0.1` encodes the Open Knowledge Format v0.1 frontmatter contract.
See the
[OKF specification](https://github.com/GoogleCloudPlatform/knowledge-catalog/blob/main/okf/SPEC.md)
for the full standard.
