manni test exposes two subcommands. [`procedures`](#test-procedures) runs
Doc Detective over the docs. [`tasks`](#test-tasks) has a synthetic user
attempt a task from them. Both report in the family contract. There is no
default subcommand. `manni test docs/` is a usage error, and the verb is
always spelled.

```sh
manni test [options] procedures [paths...] [command options]
manni test [options] tasks [targets...] [command options]
```

## Global options

Global options are accepted before the subcommand.

| Option | Description |
|---|---|
| `-V, --version` | Print the manni version and exit. |
| `-h, --help` | Print help for the program or a subcommand. |

## `test`

The docs-testing domain. Every command on this page lives under it. `test`
accepts its own `-V, --version`, which reports the manni version, and
`-h, --help`. Run with no subcommand it prints usage, exit `2`.

```sh
manni test [options] <command> [command options] [arguments]
```

`test` has no options of its own beyond those two.

## `test procedures`

Start Doc Detective, read the results file it writes, and report every
failing or warning step. Doc Detective's exit code says only whether it ran.
The verdict comes from its results.

```sh
manni test procedures [paths...] [options]
```

### Arguments

| Argument | Required | Description |
|---|---|---|
| `[paths...]` | no | Files, directories and globs to test. A file or directory goes to Doc Detective as typed, and Doc Detective walks a directory itself. manni expands a glob. Omitted: `--collection`, else Doc Detective's config `input`. |

### Options

| Option | Argument | Default | Description |
|---|---|---|---|
| `--collection` | `<name>` | none | A collection declared in `manni.config.yaml` to test. Repeatable, one name per occurrence. Cannot be combined with paths. |
| `-c, --config` | `<path>` | the nearest `manni.config.yaml` | The manni config file to read. It supplies `collections:` and `tools.doc-detective.config`. |
| `-f, --format` | `<format>` | `pretty` | Output format: `pretty`, `json` or `github`. See [output formats](#output-formats). |
| `--allow-empty` | n/a | off | Treat finding no tests, or no files, as success, exit `0`. |
| `--progress` | n/a | on a terminal | Stream Doc Detective's log to stderr as it runs. |
| `--no-progress` | n/a | off | Never stream Doc Detective's log. It is captured, and its tail is printed only when Doc Detective fails. |
| `--no-color` | n/a | off | Disable colored output. Color applies to the `pretty` output only, on a TTY, and never under `NO_COLOR`; the same [rules](/manni/meta/reference/output-and-exit-codes/#color-behavior) as the metadata tool. |

### Input precedence

A run tests the first of these that is present.

1. **Positional paths.** Each must exist, because Doc Detective skips a
   missing path without a word. A glob that matches nothing is refused too.
2. **`--collection <name>`.** The named collections' `paths:` minus their
   `exclude:`, resolved against the config file's directory. The file list
   replaces Doc Detective's `input`.
3. **Doc Detective's own `input`.** From the file `tools.doc-detective.config`
   names, else from the `.doc-detective.json`, `.doc-detective.yaml` or
   `.doc-detective.yml` Doc Detective finds in the working directory.

With no `--collection`, collections are not read. That differs from
`manni meta validate` and `manni lint check`, on purpose. Doc Detective's
config already says what to test, and it is this domain's default input.

Every other key in Doc Detective's config still applies, whichever rung
supplies the inputs. That covers `fileTypes`, `beforeAny` and
`loadVariables`.

### What manni passes Doc Detective

```sh
doc-detective -i <a>,<b>,<c> [-c <config>] -r json -o <temp dir>
```

`-i` is one comma-joined list, and appears only when manni names the inputs.
`-c` appears only when `tools.doc-detective.config` is set. manni reads the
newest `testResults-*.json` from the temporary directory, then removes the
directory. It never passes `-e`.

On Windows, manni runs Doc Detective's bin script with `node` directly rather
than through the `.cmd` shim npm installs. That lifts the command-line limit
from 8,191 characters to 32,767. A run whose inputs pass it is refused with
exit `2`.

### Parity with the other domains

Three inputs other commands take do not apply here.

- **`-` for stdin.** Doc Detective reads files and has no stdin, so `-` is a
  usage error.
- **`--as` and `--ext`.** Doc Detective's `fileTypes` decides which files hold
  tests and how to read them.
- **`--exclude`.** Doc Detective's config owns that too. A collection's own
  `exclude:` still applies, because the collection is the list.

### Output formats

All output goes to stdout. Doc Detective's log, with `--progress`, and every
error go to stderr.

**`pretty`** lists only `FAIL` and `WARNING` steps. They are grouped by page,
relative to the working directory, with the step's line when Doc Detective
reports one. A summary line of test counts follows.

Each step's message is Doc Detective's own. A `FAIL` adds one sentence, because
Doc Detective compares only what the step expected with what happened. The fix
can lie in the step, in the procedure it documents, or in the product. Two dim
lines follow the message. The first names the step's action, and the step's
own `description` when it has one. The second links the action's page in Doc
Detective's docs. A step that fails the same way in several contexts, such as
two browsers, is listed once.

```console
$ manni test procedures test/test/fixtures/fail.md
test/test/fixtures/fail.md
  4  FAIL     Returned exit code 1. Expected one of [0]. Fix the step, fix the procedure it documents, or report a product regression.
              Doc Detective runShell
              Guide: https://docs.doc-detective.com/docs/actions/runshell

1 test: 0 passed, 1 failed, 0 warnings, 0 skipped
```

A run with no failing or warning step prints the summary line alone:

```console
$ manni test procedures test/test/fixtures/pass.md
1 test: 1 passed, 0 failed, 0 warnings, 0 skipped
```

The counts are tests, from Doc Detective's `summary.tests`. A count of one
takes the singular, as in `1 test` and `1 warning`.

**`github`** writes one workflow command per listed step, `::error` for a
`FAIL` and `::warning` for a `WARNING`, then the summary line. GitHub turns
each command into an annotation on the page and line. The message carries the
same text and lines as `pretty`, joined by `%0A`.

{/* test {"testId":"test-reference-cli","description":"The reference's examples: the github format on fail.md exits 1, pass.md exits 0, and stdin is a usage error."} */}

{/* step {"description":"A passing page exits 0 in the github format, with the summary line alone.","runShell":{"command":"npx @hawkeyexl/manni test procedures test/test/fixtures/pass.md -f github --no-progress","exitCodes":[0],"stdio":"1 test: 1 passed"}} */}
{/* step {"description":"Stdin is a usage error, exit 2.","runShell":{"command":"npx @hawkeyexl/manni test procedures -","exitCodes":[2],"stdio":"Doc Detective has no stdin"}} */}
{/* test end */}

```console
$ manni test procedures test/test/fixtures/fail.md -f github
::error file=test/test/fixtures/fail.md,line=4,title=Doc Detective::Returned exit code 1. Expected one of [0]. Fix the step, fix the procedure it documents, or report a product regression.%0ADoc Detective runShell%0AGuide: https://docs.doc-detective.com/docs/actions/runshell
1 test: 0 passed, 1 failed, 0 warnings, 0 skipped
```

**`json`** prints Doc Detective's results object, verbatim. It carries
`summary`, with `pass`, `fail`, `warning` and `skipped` counts for specs,
tests, contexts and steps, and `specs[].tests[].contexts[].steps[]`. A script
written against Doc Detective's report reads it unchanged. It prints `null`
when a run with `--allow-empty` found no tests. Shortened:

```json
{
  "summary": {
    "specs": { "pass": 1, "fail": 0, "warning": 0, "skipped": 0 },
    "tests": { "pass": 1, "fail": 0, "warning": 0, "skipped": 0 },
    "contexts": { "pass": 1, "fail": 0, "warning": 0, "skipped": 0 },
    "steps": { "pass": 1, "fail": 0, "warning": 0, "skipped": 0 }
  },
  "specs": [
    {
      "specId": "test/test/fixtures/pass.md",
      "tests": [
        {
          "testId": "echo-ok",
          "contexts": [
            {
              "contextId": "default",
              "steps": [
                {
                  "runShell": { "command": "echo hello", "exitCodes": [0] },
                  "location": { "line": 4 },
                  "result": "PASS"
                }
              ]
            }
          ]
        }
      ]
    }
  ]
}
```

The shape is Doc Detective's, so it follows Doc Detective's releases.

### Progress

With progress on, Doc Detective's log streams to stderr as it runs. Progress
is on by default when stderr is a terminal. `--progress` turns it on anywhere,
which is how a CI job sees the log live. `--no-progress` turns it off. The log
is then captured, and its tail is printed only when Doc Detective exits
non-zero. stdout carries only the report either way, so `-f json` stays
parseable.

### Exit codes

| Code | Meaning |
|---|---|
| `0` | Nothing failed. `WARNING` and `SKIPPED` pass, as they do in Doc Detective. Also a run with `--allow-empty` that found no tests or no files. |
| `1` | Doc Detective's `summary` counts a failure at one of its levels, which are specs, tests, contexts and steps. The report on stdout lists the failing steps. |
| `2` | Usage or operational error. One line on stderr, prefixed `manni: `. A missing or unknown subcommand prints the help or commander's own message instead. |

### Messages

Every message below exits `2` and is printed on stderr, prefixed `manni: `.

| When | Message |
|---|---|
| `doc-detective` is not on `PATH` | `doc-detective is not on PATH. Install Doc Detective (npm install -g doc-detective) to run doc tests.` |
| No paths, no `--collection`, and no Doc Detective config | `test procedures needs paths or a Doc Detective config. Pass paths, or add .doc-detective.json.` |
| A named path does not exist | `File not found: "<path>". Check the path. Named paths resolve from the working directory.`, or `Files not found: "<a>", "<b>". Check the paths. Named paths resolve from the working directory.` for more than one |
| The paths match no files | `No files matched. Patterns tried: "<path>". Pass --allow-empty if that is expected.` |
| `-` is given | `test procedures reads files; Doc Detective has no stdin. Pass a path.` |
| `--collection` with paths | `--collection selects a configured collection; it cannot be combined with paths.` |
| `--collection` with no manni config | `--collection needs a config file to select from.` |
| An unknown collection | `no collection named "<name>" in manni.config.yaml. Configured: site.`, with a `did you mean` hint for a name that differs only in case |
| The collections match no files | `--collection matched no files. Pass --allow-empty if that is expected.` |
| `tools.doc-detective.config` names a missing file | `manni.config.yaml: tools.doc-detective.config "<path>" does not exist.` |
| The config has a `test:` section | `manni.config.yaml: test has no keys. Doc Detective's settings live under tools.doc-detective, and Claude Code's under tools.claude-code.` |
| Doc Detective exits non-zero | `Doc Detective failed (exit <n>):`, then the tail of its output. `killed before exiting` replaces `exit <n>` when it had no exit code. |
| No results file, or one that does not parse | `Doc Detective wrote no results to read. Run doc-detective directly to see why.` |
| No tests in the inputs | `Doc Detective found no tests in the inputs. Pass --allow-empty if that is expected.` |
| The inputs pass the Windows command-line limit | `the selected inputs exceed the command-line limit. Narrow the collection, or set input in the Doc Detective config.` |
| An unknown `--format` | `Unknown --format "<format>". Use pretty \| json \| github.` |

With `--allow-empty`, a missing path is skipped. Paths or collections that
match no files, and a run that found no tests, then exit `0`.

A malformed `tools.doc-detective` key stops every command that reads the
config. The [configuration reference](/manni/meta/reference/configuration/#tools)
lists those messages.

### Examples

The minimum, one page:

```sh
manni test procedures docs/guide.md
```

Doc Detective's config input, from `.doc-detective.json` in the working
directory or from `tools.doc-detective.config`:

```sh
manni test procedures
```

The pages a configured collection names, with every other setting from Doc
Detective's config:

```sh
manni test procedures --collection site
```

The CI form, with annotations and a live log:

```sh
manni test procedures -f github --progress
```

The scripting form. Doc Detective's report is on stdout, and the exit code is
the verdict:

```sh
manni test procedures -f json > results.json
```

Every option at once. Positional paths are the alternative to `--collection`:

```sh
manni test procedures --collection site --collection guides -c ci/manni.config.yaml -f github --allow-empty --no-progress --no-color
```

The usage errors, each exit `2`:

```console
$ manni test procedures
manni: test procedures needs paths or a Doc Detective config. Pass paths, or add .doc-detective.json.
$ manni test procedures -
manni: test procedures reads files; Doc Detective has no stdin. Pass a path.
$ manni test procedures docs/ --collection site
manni: --collection selects a configured collection; it cannot be combined with paths.
$ manni test procedures --collection Site
manni: no collection named "Site" in manni.config.yaml. Configured: site. Names are case-sensitive; did you mean "site"?
$ manni test procedures docs/ -f sarif
manni: Unknown --format "sarif". Use pretty | json | github.
$ manni test procedures docs/
manni: doc-detective is not on PATH. Install Doc Detective (npm install -g doc-detective) to run doc tests.
```

The first runs in a directory with no Doc Detective config, and the last on a
machine without Doc Detective.

## `test tasks`

Have a synthetic user attempt a task from a page or a journey, then judge its
trace and workspace against the docs. The synthetic user is Claude Code, run
headless in a temporary directory. It plays a persona record when the run
names one. A judge then decides each eval from what the run left behind.

```sh
manni test tasks [targets...] [options]
```

A run needs Claude Code on `PATH`, signed in, and a judge provider. The
[attempt a task](/manni/test/attempt-a-task/) page walks through a first run.

### Arguments

| Argument | Required | Description |
|---|---|---|
| `[targets...]` | no | Page paths and `http(s)://` URLs, space-separated. Each is a start, where the synthetic user begins, and each makes its own run. Omitted: each journey's `entry-point`. |

### Options

| Option | Argument | Default | Description |
|---|---|---|---|
| `--task` | `<text>` | none | The task in plain text, in the reader's words. Needs at least one target. Cannot be combined with `--journey`. |
| `--journey` | `<id>` | the golden set | A journey record to run as the task. Repeatable, one id per occurrence, and one run per journey. With neither `--task` nor `--journey`, every journey that declares `evals:` runs. |
| `--persona` | `<id>` | the journey's `personas` | A persona record for the synthetic user to play. Repeatable, one id per occurrence, and one run per persona. A `--task` with no `--persona` runs as a newcomer. |
| `--workspace` | `<dir>` | the journey's `workspace:`, else empty | The directory the synthetic user starts in. It is copied fresh into a temporary directory for each run, and the original is never touched. |
| `-c, --config` | `<path>` | the nearest `manni.config.yaml` | The manni config file to read. It supplies the collections that hold the records and the docs, `tools.claude-code` and `providers:`. |
| `-f, --format` | `<format>` | `pretty` | Output format: `pretty`, `json` or `github`. See [output formats](#output-formats-1). |
| `--provider` | `<name>` | the family's precedence | The judge's provider, as in docevals and tracevals. It overrides [`providers:`](/manni/meta/reference/configuration/#providers). |
| `--model` | `<id>` | the provider's | The judge's model. The synthetic user's model is `tools.claude-code.model`. |
| `--keep` | n/a | off | Keep each run's temporary directory, and print its workspace path to stderr. |
| `--allow-empty` | n/a | off | Treat an empty golden set as success, exit `0`. |
| `--progress` | n/a | on a terminal | Stream each action the synthetic user takes to stderr. |
| `--no-progress` | n/a | off | Never stream the synthetic user's actions. |
| `--no-color` | n/a | off | Disable colored output. Color applies to the `pretty` output only, on a TTY, and never under `NO_COLOR`; the same [rules](/manni/meta/reference/output-and-exit-codes/#color-behavior) as the metadata tool. |

### How runs are assembled

A run is one start, one task and one persona, or no persona. manni runs every
combination, one after another.

- **The task.** `--task`, or each `--journey`. With neither, the golden set
  runs, which is every journey record that declares `evals:`.
- **The start.** Each target. With none, the journey's `entry-point`.
- **The persona.** Each `--persona`. With none, each of the journey's
  `personas`. A `--task` with no `--persona` runs as a newcomer, with no
  persona.

So `--journey t1 --persona theo --persona maya` is two runs. Two targets with
two personas make four.

Journeys and personas are the strategy records the config's collections hold,
as [`manni strategy`](/manni/strategy/) reads them. A journey's `entry-point`
and `workspace` resolve against the config file's directory.

### What a journey supplies

| Field | How `test tasks` uses it |
|---|---|
| `title` | The task, as told to the synthetic user. |
| `trigger` | What started the task, told to the synthetic user. |
| `entry-point` | The start when no target is passed, as a path or a URL. |
| `success-criteria` | When the task is done, told to the synthetic user. It is judged after each run as the `success` eval. |
| `personas` | Who the synthetic user plays when no `--persona` is passed, one run each. |
| `workspace` | The directory it starts in when no `--workspace` is passed. |
| `evals` | The journey's golden evals, graded after each run. Declaring them puts the journey in the golden set. |

The journey's `description` and body are not told to the synthetic user.

An `evals:` entry is a tracevals
[eval entry](/manni/tracevals/reference/evals-schema/#object-form), with an
`id` in kebab-case that is unique in the list. Eight graders apply: `ai`,
`command`, `regex`, `file-access`, `tool-usage`, `tool-order`, `turn-count` and
`cost`. Three are refused. Nobody reviews a synthetic run, so `human` cannot
grade one. It has no skills, so `skill-invoked` has nothing to find. Its last
message is its account, so `json-output` has nothing to parse.

Graders read the workspace as their project root. A `command` runs there, and
`files` and `{ source: file, path }` read it. `{trace}` in a command is the
run's trace path. The [graders reference](/manni/tracevals/reference/graders/)
has each grader's options.

```yaml title="docs/content-strategy/journeys/t1.md"
---
type: journey
id: t1
title: Fix a failing metadata check fast
description: Theo lands on the docs from a red CI check or a search and needs a clear map from the error to the field to fix.
personas: [theo]
trigger: "The docs check on his pull request failed with: docs/install.md (root) must have required property 'description' (line 1) [manni:core:1.0.0]"
entry-point: docs/src/content/docs/meta/fix/index.mdx
success-criteria: The check passes on his repo, and the only change is the missing field in docs/install.md.
workspace: test/test/fixtures/tasks/red-pr
evals:
  - id: check-passes
    assertion: manni meta validate passes on the repo after the fix.
    grader: command
    command: [npx, --yes, "@hawkeyexl/manni", meta, validate]
    timeout-ms: 120000
  - id: description-added
    assertion: docs/install.md has a non-empty description in its frontmatter.
    grader: regex
    target: { source: file, path: docs/install.md }
    options: { pattern: "^description: \\S", flags: m }
  - id: confirmed-locally
    assertion: Theo ran the check after his fix.
    grader: tool-order
    options: { before: Edit, after: Bash, afterInputMatch: "meta validate" }
---
```

### What a persona supplies

The synthetic user is told the persona's `title`, `description`, `role`,
`team-context`, `proficiency`, `prerequisites`, `goals`, `pains` and
`constraints`. It is never told the body. A persona's prose often says how the
person uses the product, which is what the docs must teach. A persona with
only `title` and `description` still runs.

Each of the persona's `constraints` is also judged after the run, as a
`constraint` warning.

### What a start means

- **A URL.** The synthetic user is told to start there, and fetches it.
- **A path.** manni copies the docs into a `docs/` folder beside the
  workspace, and tells the synthetic user to start at the page's copy. It
  copies the collection that holds the page, or the page's directory when no
  collection holds it. The synthetic user never sees your checkout.

A path start reads source, so components and links read as they are written.
To test what readers see, serve the site and pass its URL.

### What manni passes Claude Code

Each run gets a fresh temporary directory:

```text
<tmp>/manni-task-XXXX/
  workspace/   a copy of the seed; Claude Code's working directory
  docs/        a copy of the docs, for a path start only
  global/      the npm global prefix for this run
  role.md      the role prompt below
```

Claude Code is found on `PATH`, as Doc Detective is. manni starts it like
this:

```text
claude -p
  --output-format stream-json --verbose
  --no-session-persistence
  --setting-sources ""
  --append-system-prompt-file <tmp>/role.md
  --tools Read,Write,Edit,Glob,Grep,Bash,WebFetch
  --allowedTools Read,Write,Edit,Glob,Grep,Bash,WebFetch[,mcp__<each server in mcpConfig>]
  --permission-mode dontAsk
  --strict-mcp-config [--mcp-config <tools.claude-code.mcpConfig>]
  --max-turns <tools.claude-code.maxTurns>
  [--model <tools.claude-code.model>]
  [--add-dir <tmp>/docs]
cwd:   <tmp>/workspace
stdin: the task brief below
env:   NPM_CONFIG_PREFIX=<tmp>/global, with its bin directory first on PATH
```

- **None of your setup.** `--setting-sources ""` loads none of your Claude
  Code settings. So none of your plugins, hooks or MCP servers reach the
  synthetic user. It does use your Claude Code sign-in.
- **Seven tools.** The synthetic user has Read, Write, Edit, Glob, Grep, Bash
  and WebFetch, plus the servers `tools.claude-code.mcpConfig` names.
  `--tools` hides every other tool, web search included, because the test is
  whether these docs are enough. Bash is the one terminal on every platform,
  so a journey's `tool-order` eval can name it.
- **Global installs stay in the run.** Docs often say `npm install -g`.
  `NPM_CONFIG_PREFIX` sends a global npm install to the run's `global/`
  directory, which goes when the run does.

The role prompt, `role.md`:

```text
You are taking part in a usability test of some documentation. You are playing
a person, not an assistant. Stay in that person's shoes for the whole session.

Who you are:
<title>. <description>
Role: <role>
Team: <team-context>
Already good at: <proficiency, one per line>
Knows before starting: <prerequisites>
Wants: <goals>
Frustrated by: <pains>
Your constraints:
- <each constraint>

How to work:
- Use what the documentation tells you, and what this person would already know.
- Nobody is available to answer questions. When stuck, do what this person
  would do, or give up.
- The current directory is yours. Treat the documentation as read-only.
- When you finish or give up, end with a short account in this person's voice:
  whether you got it done, where you got stuck, and what in the docs helped or
  confused you.
```

Each line under "Who you are" appears only when its field is set. With no
persona, that section reads `Someone new to this product, with the task below
and no other context.`

The task brief, on stdin:

```text
<the --task text, or the journey's title>
What started this: <trigger>
You're done when: <success-criteria>
Start here: <URL>  |  Start here: ../docs/<page path in the copy>
```

The two middle lines appear only for a journey that sets the field.

### What manni keeps

The trace is Claude Code's stdout stream. manni saves it as
`.manni/test/tasks/<run-id>/trace.jsonl`, beside the config file. `role.md`
and `brief.md` sit beside it.
`<run-id>` is `<UTC timestamp>-<journey id or "task">-<persona id or "newcomer">`.

The temporary directory is removed after judging. `--keep` keeps it, and
prints its workspace path to stderr.

### Safety

The synthetic user runs the commands the docs tell it to, with your
privileges and your network. Doc Detective's shell steps do the same. Its
working directory is a temporary copy, but its terminal is not confined. A
global npm install stays in the run, and anything else it changes stays
changed.

Run tasks from docs you do not trust in CI or in a container.
[`manni check`](/manni/family/check/) never runs `manni test tasks`.

### What the judge sees

Every judged eval gets the same evidence, gathered after the run.

- **The trace.** Each user, assistant and tool event. Each tool result is cut
  to 2,000 characters.
- **The workspace.** The files the run added, changed or removed against the
  seed. Each added or changed text file's contents are cut to 4,000
  characters, and 20,000 in all.
- **The docs the reader had.** The start page and every page it opened, as
  the trace recorded them, from a Read of the docs copy or a WebFetch result.
  They are cut to 40,000 characters in all, start page first. The output
  lists them under `docs`.

The judge is the family's. `--provider` and `--model` come first, then
`providers:`, then `auto`. Each verdict is `pass`, `fail` or `needs-review`,
with a confidence and its reasoning. [Choose a
provider](/manni/docevals/judge/choose-a-provider/) covers each provider.

### Evals on every run

| Eval | When | Grader | Severity | Annotated at |
|---|---|---|---|---|
| `success` | The journey sets `success-criteria`. | `ai` | error | Its line in the journey. |
| Each `evals:` entry | The journey declares them. | Its own | Its own | Its line in the journey. |
| `completed` | The run has neither of the above, as every `--task` run does. | `ai` | error | The task's source. |
| `followed-the-docs` | Always. | `ai` | warning | The task's source. |
| `constraint` | Once per persona constraint. | `ai` | warning | Its line in the persona. |

The task's source is the journey's `title:` line, or line 1 of the start page.
A URL start has no location.

`success` asserts the journey's `success-criteria`, and `constraint` asserts
the constraint. `completed` asserts the task in its own words:

```text
The reader completed the task: <the --task text, or the journey's title>
```

`followed-the-docs` asserts this:

```text
Every step the reader took came from the docs it had, or from what the persona already knows. It did not guess or lean on outside knowledge.
```

It is what makes a success mean the docs worked. An agent that already knows
the product could finish without them.

`completed` judges the task's words and nothing more. A criterion beyond them,
such as the one file a fix may change, belongs in a journey's
`success-criteria` or `evals:`.

A run **passes** when no `error`-severity eval failed, errored or needs
review. `needs-review` fails the run, as `manni tracevals run` does by
default.

### Progress

With progress on, each run prints a start line to stderr, then one line per
tool call:

```text
task as newcomer: starting in an empty directory
  newcomer › Bash curl -s http://127.0.0.1:4321/manni/meta/get-started/ | sed 's/<[^>]*>//g' | gre
  newcomer › Bash node --version; npm --version
  newcomer › Bash npm install -g @hawkeyexl/manni 2>&1 | tail -20
  newcomer › Bash manni --version
```

A run with no workspace says `starting in an empty directory`. Each tool line
carries the first 80 characters of the tool's main input. Progress is on by
default when stderr is a terminal. `--progress` turns it on anywhere, and
`--no-progress` turns it off.

`--keep` prints one line per run to stderr, such as
`manni: kept t1 as theo's workspace: <absolute path>`.

### Exit codes

| Code | Meaning |
|---|---|
| `0` | Every run passed. Warnings and notices pass. Also an empty golden set with `--allow-empty`. |
| `1` | A run failed. An `error`-severity eval in it failed, errored or needs review. |
| `2` | Usage, config or record error, Claude Code missing or stopping without a result, or no judge available. One line on stderr, prefixed `manni: `. |

A run that reaches the turn limit is judged, not an error. A run where Claude
Code exits without a result stops the command with exit `2`. That covers a
machine that is not signed in, an API error and a crash.

### Messages

Every message below exits `2` and is printed on stderr, prefixed `manni: `.

| When | Message |
|---|---|
| A bare run, and no journey declares `evals:` | `nothing to run: no journey declares evals:. Pass --task with a page or URL, or --journey <id>.` With `--allow-empty`, stdout prints `No tasks to run.` and the exit is `0`. |
| A target with neither `--task` nor `--journey` | `a start page needs a task. Pass --task "<what the reader wants>" or --journey <id>.` |
| `--task` with no target | `--task needs a page or URL to start from.` |
| `--task` and `--journey` together | `--task and --journey both name the task. Pass one.` |
| `-` as a target | `manni test tasks reads no stdin. Pass a page path or URL.` |

| An id with no record | `no record "t9". 82 records; did you mean "t1"?` |
| An id of the wrong record type | `"m1" is a journey; --persona takes a persona.`, or `"theo" is a persona; --journey takes a journey.` |
| A journey with no start | `journey "t1" has no entry-point:. Add one to docs/content-strategy/journeys/t1.md, or pass the page to start from.` |
| A journey names a persona with no record | `journey "t1" names persona "tim", which has no record.` |
| A grader that cannot grade a task | `docs/content-strategy/journeys/t1.md:19: evals[1].grader "human" cannot grade a task. Use ai, command, regex, file-access, tool-usage, tool-order, turn-count or cost.` |

| `tools.claude-code.model` is not a string | `manni.config.yaml: tools.claude-code.model must be a non-empty string.` |
| `tools.claude-code.maxTurns` is not a positive integer | `manni.config.yaml: tools.claude-code.maxTurns must be a positive integer.` |
| `tools.claude-code.mcpConfig` names a missing file | `manni.config.yaml: tools.claude-code.mcpConfig "<path>" does not exist.` |
| An unknown key under `tools.claude-code` | `manni.config.yaml: tools.claude-code has unknown key "<key>". Supported keys: model, maxTurns, mcpConfig.` |

No judge provider at all prints the family's provider message,
which [Choose a provider](/manni/docevals/judge/choose-a-provider/#no-provider-at-all)
shows.

One warning leaves the exit code and the report alone. A process the synthetic
user started, such as a browser, can outlive the run and hold a file in its
temp directory. Windows then refuses the removal, and manni says so on stderr:

```text
manni: could not remove <temp dir> after t1 as theo: EBUSY: resource busy or locked, rmdir '<path>'. A process the synthetic user started may still hold it; remove it by hand.
```

### Parity with the other domains

- **No `--collection`.** Journeys and personas come from the strategy records,
  wherever the config's collections hold them. A path start copies the
  collection that holds the page.
- **No `-` for stdin.** A start is a page or a URL, so `-` is a usage error.
- **No `--as`, `--ext` or `--exclude`.** A target is where a reader starts,
  not a set of files to read.
- **`--provider` and `--model` mean the judge**, as in every domain with one.
  The synthetic user's model is set only in `tools.claude-code.model`.

```sh
manni test tasks docs/src/content/docs/meta/get-started/index.mdx --task "Install manni and check which version you have"
```

```sh
manni test tasks http://127.0.0.1:4321/manni/meta/get-started/ --task "Install manni and check which version you have"
```

```sh
manni test tasks docs/src/content/docs/meta/index.mdx --journey t1
```

```sh
manni test tasks --journey t1 --persona theo --persona maya
```

```sh
manni test tasks
```

```sh
manni test tasks -f github --no-progress
```

```sh
manni test tasks -f json --no-progress | jq '[.runs[] | {journey, persona, outcome, costUsd: .usage.costUsd}]'
```
