{/* cite ten-fields */}
{/* cite fields-flat-at-root */}
A term entry is a record. A term page carries it in its metadata, and a
manifest entry holds the same record. Every reader produces it from a body
construct or a TBX entry too. The fields sit at the root of the page, flat.
They are the built-in
[`manni:terminology:1.2.0`](/manni/meta/reference/schemas/manni-terminology/)
vocabulary.

Ten fields carry the term's names, its meaning and its place among other
terms. They map onto SKOS, and they are the whole of 1.0.0. Six more tie the
term to other vocabularies. The rest of the record holds the TBX data
categories a translation system exchanges. A page that carries none of them is
a 1.0.0 page, and it stays valid.

## Marking a file

| `type:` | Means |
|---|---|
| `term` | The file is one entry. Its record is the file's metadata. |
| `term-set` | The file holds many entries, in its body. Required for a Markdown or MDX definition list and an HTML `<dl>`, which do not say what they are. |

{/* cite self-declaring-dita */}
{/* cite self-declaring-docbook */}
{/* cite self-declaring-asciidoc */}
{/* cite self-declaring-rst */}
A DITA `<glossentry>` or `<glossgroup>`, a DocBook `<glossary>`, an AsciiDoc
`[glossary]` list and a `.. glossary::` directive are read without
`type: term-set`, because each construct declares itself. So is a `.tbx`
file, whose root element names it TBX, and a `.ttl` or `.jsonld` file you
name, which holds SKOS. `type`, `id` and `language` belong to the `manni:core`
vocabulary, and a term page uses them as any page does.

```markdown title="docs/terms/progressive-lens.md"
---
type: term
id: progressive-lens
label: progressive lens
alt-labels: [PAL, graduated lens]
hidden-labels: [no-line bifocal]
broader: [corrective lens]
abstract: Lenses that correct presbyopia without a visible line.
definition: >-
  Corrective lenses whose optical power increases continuously from the top of
  the lens to the bottom, correcting presbyopia without the visible boundary a
  bifocal carries.
---
```

## The fields

| Field | Type | Required | SKOS | What it holds |
|---|---|---|---|---|
| `label` | string | yes | `skos:prefLabel` | The one preferred name. |
| `definition` | string | no | `skos:definition` | What the term means, in full. An entry carries it unless it redirects with `see`. |
| `abstract` | string | no | none | The short form, one sentence, for a hover card or a tooltip. |
| `alt-labels` | string or list | no | `skos:altLabel` | Other admitted names, such as synonyms, abbreviations and spelling variants. |
| `hidden-labels` | string or list | no | `skos:hiddenLabel` | Names the term must not go by, such as deprecated spellings, obsolete forms and misspellings. |
| `broader` | string or list | no | `skos:broader` | Labels or ids of the parent terms. |
| `narrower` | string or list | no | `skos:narrower` | Labels or ids of the child terms. |
| `related-terms` | string or list | no | `skos:related` | Labels or ids of associated terms. |
| `see` | string | no | none | The label or id of the entry this one redirects to. |
| `scope-note` | string | no | `skos:scopeNote` | How far the term reaches in this set, and where it stops. |

{/* cite label-list-string-or-list */}
{/* cite list-trim-drop-empty */}
{/* cite no-label-skipped */}
A list field takes one string or a list. Readers trim each value and drop
empty ones, so `" bifocal "` and `bifocal` are the same label. A page with
`type: term` and no `label` is skipped, with a notice on stderr:

```
manni: no-label.md:1: skipped a page entry with no term.
```

{/* cite one-value-field-ignored */}
{/* cite one-value-field-rest-read */}
A one-value field (`definition`, `abstract`, `see`, `scope-note`) takes text.
Given a list or a mapping, the reader leaves that field out, reads the rest of
the entry, and says so on stderr:

```
manni: varifocal.md:5: ignored see on "varifocal": a see holds one value, not a list.
```

`definition` is optional in the schema, so a term page can land before
anyone writes its meaning. `manni term check` reports an entry with neither a
`definition` nor a `see` as
[`missing-definition`](/manni/term/reference/rules/#missing-definition), at
error. The [strict overlay](#validating-the-shape) requires one of the two.

## Mapping to other vocabularies

{/* cite mapping-fields */}
These fields say where the term sits outside this termbase. Each match field
takes one IRI or a list of them, and each maps to its SKOS property:

| Field | Type | SKOS | What it holds |
|---|---|---|---|
| `notation` | string | `skos:notation` | A code that identifies the concept in another system. |
| `exact-matches` | IRI or list | `skos:exactMatch` | The same concept in another vocabulary. Use it sparingly. |
| `close-matches` | IRI or list | `skos:closeMatch` | A near-equivalent concept elsewhere. This is the common case. |
| `broad-matches` | IRI or list | `skos:broadMatch` | A broader concept in another vocabulary. |
| `narrow-matches` | IRI or list | `skos:narrowMatch` | A narrower concept in another vocabulary. |
| `related-matches` | IRI or list | `skos:relatedMatch` | An associated concept in another vocabulary. |

```yaml
type: term
id: progressive-lens
label: progressive lens
definition: Corrective lenses whose power increases from the top of the lens to the bottom.
notation: OPT-0412
exact-matches: https://www.wikidata.org/wiki/Q1424588
close-matches:
  - http://id.loc.gov/authorities/subjects/sh85107289
```

A mapping has one kind. An IRI listed under two of the five match fields of
one entry is
[`conflicting-matches`](/manni/term/reference/rules/#conflicting-matches).
A match names a concept in another vocabulary. Inside this termbase the
relation is `broader`, `narrower` or `related-terms`, and `manni graph check`
reports a match that points back into the scheme.

## One term per language

A term holds one language. A concept with names in English and German is two
terms that share an `id`. Each names its `language`, from `manni:core`:

```markdown title="docs/terms/de/progressive-lens.md"
---
type: term
id: progressive-lens
language: de
label: Gleitsichtglas
alt-labels: [Gleitsichtbrille]
definition: Brillenglas mit stufenlos zunehmender Wirkung.
---
```

A manifest entry carries `language` beside its fields. A TBX entry reads as one
term per language section, each with the entry's id and the section's
`xml:lang`. A section without one takes the root element's. A term that names
no language counts as `en`, in `manni term check` and in every render.

`term check` compares names within a language, and joins the languages on
`id`. The [rules reference](/manni/term/reference/rules/#languages) says how
each rule reads a set in more than one language.

## The TBX data categories

Version 1.1.0 holds every TBX-Basic and TBX-Linguist data category as a named
field. A TBX termbase reads into pages, and the pages write back as TBX
without loss.

### Three levels

TBX states a value about the concept, about one language, or about one
designation of the term. The level of a value is where it sits in the record:

| Level | Where it sits | TBX element |
|---|---|---|
| concept | `concept-entry` | `termEntry` (v2), `conceptEntry` (v3) |
| language | the root of the record | `langSet` (v2), `langSec` (v3) |
| term | a `designations` item | `tig` or `ntig` (v2), `termSec` (v3) |

```yaml
type: term
id: progressive-lens
language: en
label: progressive lens
alt-labels: [PAL]
hidden-labels: [no-line bifocal]
definition: Corrective lenses whose power increases continuously.  # language level
concept-entry:                                                      # concept level
  subject-field: optics
designations:                                                       # term level
  - term: progressive lens
    part-of-speech: noun
    term-type: fullForm
  - term: PAL
    term-type: acronym
  - term: no-line bifocal
    administrative-status: superseded
```

`concept-entry` says the same thing on every language's term of the id. When
the terms disagree, a TBX render keeps the first term's value and says so.

### Fields at every level

These are valid at the root, in `concept-entry`, and in a `designations` item:

| Field | Type | TBX | What it holds |
|---|---|---|---|
| `definition` | string | `descrip type="definition"` | What the term means at this level. One value. |
| `subject-field` | string | `descrip type="subjectField"` | The subject field. One value. |
| `contexts` | string or list | `descrip type="context"` | Sentences that show the term in use. |
| `notes` | string or list | `note` | Free-text notes. |
| `sources` | string or list | `admin type="source"` | Where the information came from. |
| `customer-subsets` | string or list | `admin type="customerSubset"` | The customers the entry applies to. |
| `project-subsets` | string or list | `admin type="projectSubset"` | The projects the entry applies to. |
| `cross-references` | list | `ref type="crossReference"` | Links to other entries. |
| `external-cross-references` | list | `xref type="externalCrossReference"` | Links outside the termbase, usually URLs. |
| `graphics` | list | `xref type="xGraphic"` | Images that illustrate the concept. |
| `transactions` | list | `transacGrp` | The entry's history. |
| `tbx-elements` | list of XML strings | anything else | [Pass-through](#pass-through), in source order. |

A link item is a target, or a mapping of `target` and an optional `text`:

```yaml
cross-references:
  - spectacle-lens
  - target: corrective-lens
    text: corrective lens
```

A `transactions` item names its `type`, and may give a `date` and a
`responsibility`. The date is kept as written:

```yaml
transactions:
  - type: origination
    date: 2024-03-01
    responsibility: Maya
```

### Fields of a designation

A `designations` item names the designation it describes in `term`. Its other
keys are valid only there:

| Field | Type | TBX | Values TBX names |
|---|---|---|---|
| `term` | string, required | `term` | The entry's `label`, one of its `alt-labels` or one of its `hidden-labels`. |
| `administrative-status` | string | `termNote type="administrativeStatus"` | `preferred`, `admitted`, `deprecated`, `superseded`, `none` |
| `part-of-speech` | string | `termNote type="partOfSpeech"` | `adjective`, `noun`, `other`, `verb`, `adverb`, `properNoun` |
| `grammatical-gender` | string | `termNote type="grammaticalGender"` | `masculine`, `feminine`, `neuter`, `other` |
| `grammatical-number` | string | `termNote type="grammaticalNumber"` | `singular`, `plural`, `dual`, `mass`, `otherNumber` |
| `term-type` | string | `termNote type="termType"` | `fullForm`, `acronym`, `abbreviation`, `shortForm`, `variant`, `phrase` |
| `term-location` | string | `termNote type="termLocation"` | `checkBox`, `menuItem`, `pushButton`, `toolTip` and the other interface elements of the TBX-Basic picklist |
| `geographical-usage` | string | `termNote type="geographicalUsage"` | A region or a locale. |
| `register` | string | `termNote type="register"` | `colloquialRegister`, `neutralRegister`, `technicalRegister`, `in-houseRegister`, `bench-levelRegister`, `slangRegister`, `vulgarRegister` |
| `reading` | string | `admin type="reading"` | How the designation is read aloud. |
| `reading-note` | string | `adminNote type="readingNote"` | A note on the reading. |
| `transfer-comments` | string or list | `termNote type="transferComment"` | Notes for the translator. |

`register`, `grammatical-number`, `reading`, `reading-note` and
`transfer-comments` are TBX-Linguist categories. The rest are TBX-Basic. A
designation key at the root or in `concept-entry` is not a terminology field
there, and the reader leaves it alone.

A designation that has no item still has the status its kind of label gives
it. An item whose `term` names none of the entry's labels is ignored, with a
notice on stderr:

```
manni: pal.md:7: ignored designations item "progresive lens" on "progressive lens": it names no label, alt-label or hidden-label.
```

`designations` is a list rather than a mapping, so the order of a TBX entry
and a homograph both survive. A label no item names follows the items, in
label, alt-label, hidden-label order.

### Picklists

A picklist value is kept as written, whether `fullForm`, `Verb` or `pronoun`.
The open vocabulary types it as a string, so a TBX file from any vendor reads.
The strict overlay,
[`manni:terminology-strict:1.2.0`](/manni/meta/reference/schemas/manni-terminology/#strict-overlay),
closes each picklist to the values TBX names:

```console
$ manni meta validate --no-config -s manni:terminology:1.2.0 -s manni:terminology-strict:1.2.0 strict-picklist-verb.md
✗ strict-picklist-verb.md
    /designations/0/part-of-speech  must be equal to one of the allowed values  (line 7)  [manni:terminology-strict:1.2.0]

1 file checked, 0 passed, 1 failed, 1 error
```

## The kind of label is the status

{/* cite status-is-the-kind-of-label */}
The field a name sits in says how it may be used. That is its status, unless a
`designations` item names another:

| Field | Status | Where the status shows |
|---|---|---|
| `label` | preferred | TBX `preferredTerm-admn-sts`. The casing rules of the Vale style. |
| `alt-labels` | admitted | TBX `admittedTerm-admn-sts`. The casing rules, and the first-use rule for an all-caps acronym. |
| `hidden-labels` | deprecated | TBX `deprecatedTerm-admn-sts`. `Terms.Deprecated` in the Vale style, which swaps the name for the label. |

TBX names more statuses than there are kinds of label. A TBX reader puts each
designation where its status says. It writes `administrative-status` where the
kind alone would not give the status back:

| TBX `administrativeStatus` | Read as |
|---|---|
| `preferredTerm-admn-sts` | The `label`. A second preferred designation is an alt-label with `administrative-status: preferred`. |
| `admittedTerm-admn-sts` | An alt-label. |
| `deprecatedTerm-admn-sts` | A hidden-label. |
| `supersededTerm-admn-sts` | A hidden-label with `administrative-status: superseded`. |
| any other value | An alt-label, with the value as written. |
| no status | An alt-label with `administrative-status: none`. |

When no designation is preferred, the first one is the label, and its item says
`administrative-status: none`. A TBX render writes no status element for
`none`.

## Pass-through

Two fields carry what no named field can, so the TBX a term was read from
writes back as it was.

**`tbx-elements`** holds elements whole, as XML strings in source order, at
the level they sat. A TBX reader puts an element there when writing the named
field would not reproduce it. That covers a vendor category, an extra
attribute, a second value of a one-value category, and a group shaped
otherwise than manni writes one:

```yaml
concept-entry:
  subject-field: optics
  tbx-elements:
    - <descrip type="Client">Acme</descrip>
```

**`tbx-markup`** holds the marked-up form of a value, as inline XML. The named
field holds the plain text, which `check`, Vale and every other render read. A
TBX render writes the item in place of the value whose text it matches:

```yaml
contexts: [Fit the progressive lens first.]
tbx-markup:
  - Fit the <hi type="bold">progressive lens</hi> first.
```

An edited value no longer matches its item, so the stale markup is never
written. Two values of one term can read as the same text with different
markup, such as a marked-up `H<hi type="subscript">2</hi>O` and a plain `H2O`.
The reader then keeps one element whole in `tbx-elements`, never the `<term>`,
so neither value gains the other's markup. The strict overlay requires each `tbx-elements` item to start with `<`.

## The `see` redirect

{/* cite see-redirect-no-definition */}
An entry with `see` points a reader at the entry that defines the term. It
names the term, and carries no definition:

```yaml
type: term
id: varifocal
label: varifocal
see: progressive-lens
```

{/* cite see-resolves-labels-ids */}
{/* cite see-is-reference-field */}
{/* cite see-not-empty-finding */}
{/* cite see-dangling-reference */}
`see` resolves against labels and ids, ignoring case. An entry with both `see`
and a `definition` is the [`see-not-empty`](/manni/term/reference/rules/#see-not-empty)
finding. A `see` that names nothing is
[`dangling-reference`](/manni/term/reference/rules/#dangling-reference).

## How an entry gets its id

{/* cite id-order */}
An entry's `id` is, in order:

1. the record's own `id`;
2. the construct's identifier: `<dt id>` or `<dfn id>` in HTML, `xml:id` on a
   DocBook `<glossentry>`, `@id` on a DITA topic, `id` on a TBX entry;
3. the slug of the preferred label, so `progressive lens` is
   `progressive-lens`.

Every language of a TBX entry takes the entry's id. An entry without one takes
the slug of its first language's label.

{/* cite id-names-get */}
{/* cite id-names-manifest-key */}
{/* cite id-names-directory-file */}
The id is what `manni term get` and a manifest key name, and what a render
into one file per entry names each file after.

## Validating the shape

{/* cite schema-requires-label-only */}
`manni term check` checks the set. The shape of one page is a schema's job.
That schema is the built-in `manni:terminology:1.2.0`, and
`manni meta validate -s` takes its id. It requires `label` on a `type: term`
page, and nothing else. A page with neither a `definition` nor a `see` passes
it, and `term check` reports that page as `missing-definition`.

{/* cite strict-requires-definition-or-see */}
The strict overlay, `manni:terminology-strict:1.2.0`, requires a
`definition` or a `see` on a `type: term` page. Stack it to fail such a page
at validation as well:

```console
$ manni meta validate --no-config -s manni:terminology:1.2.0 -s manni:terminology-strict:1.2.0 term-without-definition-or-see.md
✗ term-without-definition-or-see.md
    (root)  must have required property 'definition'  (line 1)  [manni:terminology-strict:1.2.0]
    (root)  must have required property 'see'  (line 1)  [manni:terminology-strict:1.2.0]
    (root)  must match a schema in anyOf  (line 1)  [manni:terminology-strict:1.2.0]
    (root)  must match "then" schema  (line 1)  [manni:terminology-strict:1.2.0]

1 file checked, 0 passed, 1 failed, 4 errors
```
