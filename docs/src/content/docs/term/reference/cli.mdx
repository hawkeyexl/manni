{/* cite bare-term-exits-2 */}
manni term exposes seven verbs. [`list`](#term-list), [`get`](#term-get),
[`check`](#term-check), [`lint`](#term-lint) and [`write`](#term-write) read a
term set. [`fill`](#term-fill) reads it with the pages that name its concepts,
and writes the pages it lacks. [`formats`](#term-formats) reads nothing and
lists what the others can read and write. There is no default. A bare `manni term` prints usage and
exits `2`.

```sh
manni term [options] <command> [command options] [arguments]
```

## Global options

Global options are accepted before the subcommand.

| Option | Description |
|---|---|
| `-V, --version` | Print the manni version and exit. |
| `-h, --help` | Print help for the program or a subcommand. |

## `term`

{/* cite term-version-flag */}
{/* cite term-no-subcommand-exits-2 */}
The terminology tool. Every command on this page lives under it. `term`
accepts its own `-V, --version`, which reports the manni version, and
`-h, --help`. Run with no subcommand, it prints its usage to stderr and exits
`2`.

```sh
manni term [options] <command> [command options] [arguments]
```

## The shared input model

`list`, `get`, `check`, `lint` and `write` read the set the same way, with the
same flags. They are the flags `manni meta` and `manni cite` take for the same
jobs.

- **Paths are positional.** Files, directories and globs, space-separated.
  Without them the run reads every configured
  [collection](/manni/meta/reference/configuration/#collections). Every run
  that loads a config also reads the manifests
  [`term.manifests`](/manni/term/reference/configuration/#keys) names.
- **A named `.yaml`, `.yml` or `.json` file is a manifest.** It's read exactly
  as a `term.manifests` entry is. Only a path you type counts: a directory or
  glob walk never picks those files up.

  ```sh
  $ manni term list terms.yaml
  bifocal   bifocal
  1 term
  ```
- **A `.tbx` file is a TBX termbase.** It's read when you name it, when a
  directory or glob walk finds it, and when `term.manifests` lists it. The
  root element says the version: `<martif>` is TBX v2, and `<tbx>` is TBX v3.
  Each entry is a term per language it holds, all with the entry's id.
- **A named `.ttl` or `.jsonld` file is a SKOS concept scheme.** It's read
  when you name it and when `term.manifests` lists it. A directory or glob
  walk never picks one up, because `manni graph build` writes Turtle too. Each
  `skos:Concept` is a term per language its `skos:prefLabel` holds, all with
  the id its IRI ends in. A JSON-LD file that names a remote `@context` is
  refused, because reading a termbase never fetches anything.
- **`-` reads stdin**, alongside any named paths. It needs `--as <format>`,
  which names one of the metadata tool's
  [extractors](/manni/meta/reference/formats/), or `tbx`, or `skos`. The
  extractors are `markdown`, `mdx`, `asciidoc`, `rst`, `html` and `xml`.
  `--as skos` reads JSON-LD when the first character that isn't whitespace is
  `{` or `[`, and Turtle otherwise.
- **Every file contributes references.** A page's `concepts:` and its
  `graph.concepts` are read whether or not the page holds a term. So is its
  `graph:` block's `label`, `broader`, `narrower` and `related-concepts`.
- **No terms is an error.** A run that reads files but finds no entry exits
  `2`, unless `--allow-empty` or `term.allowEmpty` says an empty set is fine.

A term is a page declaring `type: term`, or an entry in a file that holds a
list of terms. The [terminology reference](/manni/term/reference/terminology/)
has the record, and [Move and hand off a
termbase](/manni/term/set-up/move-and-hand-off/#what-each-construct-holds) has
every construct that is read.

Reading a set prints three notices of its own on stderr. None moves the exit
code:

```
manni: glossary.tbx:18: skipped a TBX entry with no term.
manni: pal.md:7: ignored designations item "progresive lens" on "progressive lens": it names no label, alt-label or hidden-label.
manni: vocab.ttl: skos:changeNote is not a term field, so 3 values were not read.
```

The first is a TBX language section that holds no `<term>`. The second is a
[`designations`](/manni/term/reference/terminology/#fields-of-a-designation)
item that names none of the entry's labels. The third is a SKOS property no
term field holds, said once per property per file.

## `term list`

List the resolved entries, one row per entry.

```sh
manni term list [paths...] [options]
```

### Arguments

| Argument | Description |
|---|---|
| `[paths...]` | Files, directories, or globs to read. Use `-` to read from stdin, with `--as`. Optional. Without paths the run covers every configured collection. See [the shared input model](#the-shared-input-model). |

### Options

| Option | Argument | Default | Description |
|---|---|---|---|
| `--as` | `<format>` | n/a | Input format for stdin. Required with `-`. |
| `--ext` | `<list>` | supported extensions and `tbx` | Comma-separated extensions kept when expanding directories and globs. Given once. |
| `--exclude` | `<glob>` | n/a | Glob to exclude from directory and glob walks. Repeatable, one glob per occurrence. |
| `--collection` | `<name>` | every collection | Read one configured collection rather than every declared one. Repeatable, one name per occurrence. Cannot be combined with positional paths (exit 2). |
| `--allow-empty` | n/a | off | Treat a missing path, no matched files or no terms as success rather than an error (exit 2). Wins over config `allowEmpty:`. |
| `--no-gitignore` | n/a | on | Read files `.gitignore` covers as well. Wins over config `respectGitignore:`. |
| `-c, --config` | `<path>` | discovered | Path to a [config file](/manni/term/reference/configuration/). The file must exist (exit 2). |
| `--no-color` | n/a | off | Disable colored output. Color applies on a TTY only, and never under `NO_COLOR`. |
| `-f, --format` | `<pretty\|json\|csv>` | `pretty` | Output format. An unknown value is an error (exit 2). |

### Output

{/* cite list-pretty-shape */}
`pretty` prints the id, the preferred label, and the alt-labels, then a count:

```
bifocal            bifocal
corrective-lens    corrective lens
progressive-lens   progressive lens   PAL, graduated lens
3 terms
```

A set in more than one language adds the language after the id. A concept has
a row per language:

```
progressive-lens   en   progressive lens   PAL
progressive-lens   de   Gleitsichtglas     Gleitsichtbrille
bifocal            en   bifocal
bifocal            de   Bifokalglas
4 terms
```

{/* cite list-csv-shape */}
`csv` prints a header and one row per entry. A list field joins its values
with `|`. The last column is the entry's language, empty when it names none:

```
id,label,alt-labels,abstract,language
corrective-lens,corrective lens,,,
progressive-lens,progressive lens,PAL|graduated lens,Lenses that correct presbyopia without a visible line.,
```

{/* cite list-json-shape */}
`json` prints `{ "terms": [...] }`. Each entry carries `id`, `language` when
the entry has one, and every field the record holds, spelled as the
[vocabulary](/manni/term/reference/terminology/) spells it. That includes
`concept-entry`, `designations`, `tbx-elements` and `tbx-markup`.

### Exit codes

| Code | Meaning |
|---|---|
| `0` | The set was listed. |
| `2` | Operational or usage error. See [usage errors](#usage-errors). |

## `term get`

{/* cite get-shows-file-line */}
Show one entry, with the file and line it was read from.

```sh
manni term get <term> [paths...] [options]
```

### Arguments

| Argument | Description |
|---|---|
| `<term>` | The entry's `id`, else its preferred `label` in any case, else one of its `alt-labels` in any case. When several entries share an alt-label, the first one read is shown. |
| `[paths...]` | Files, directories, or globs to read, exactly as on [`list`](#term-list). |

### Options

| Option | Argument | Default | Description |
|---|---|---|---|
| `--as` | `<format>` | n/a | Input format for stdin. Required with `-`. |
| `--ext` | `<list>` | supported extensions | Comma-separated extensions kept when expanding directories and globs. |
| `--exclude` | `<glob>` | n/a | Glob to exclude. Repeatable. |
| `--collection` | `<name>` | every collection | Read one configured collection. Repeatable. |
| `--allow-empty` | n/a | off | Treat a missing path, no matched files or no terms as success. |
| `--no-gitignore` | n/a | on | Read files `.gitignore` covers as well. |
| `-c, --config` | `<path>` | discovered | Path to a config file. |
| `--no-color` | n/a | off | Disable colored output. |
| `-f, --format` | `<pretty\|json>` | `pretty` | Output format. `json` prints the entry's record, with `id`. |

### Output

```
progressive lens                        docs/terms/progressive-lens.md:1
  id             progressive-lens
  alt-labels     PAL, graduated lens
  hidden-labels  no-line bifocal
  broader        corrective lens
  abstract       Lenses that correct presbyopia without a visible line.
  definition     Corrective lenses whose optical power increases continuously
                 from the top of the lens to the bottom, correcting presbyopia
                 without the visible boundary a bifocal carries.
```

A row shows each field the record holds. `concept-entry` lists its fields,
and `designations` has a line per item. `tbx-elements` counts the items at
each level, and `other languages` names the entry's terms in other languages:

```
progressive lens                        glossary.tbx:15
  id               progressive-lens
  language         en
  alt-labels       PAL
  hidden-labels    no-line bifocal
  definition       Corrective lenses whose power increases continuously.
  concept-entry    subject-field: optics
  designations     progressive lens: part-of-speech noun, term-type fullForm
                   PAL: term-type acronym
                   no-line bifocal: administrative-status superseded
  tbx-elements     1 in concept-entry
  other languages  de (Gleitsichtglas)
```

A count at the root reads `1 at the root`, and one on a designation reads
`1 on PAL`. The key column widens only when a longer key is shown.

### Exit codes

| Code | Meaning |
|---|---|
| `0` | The entry was found and printed. |
| `2` | No entry matched, or an operational or usage error. The message names the set's size and the nearest id or label. |

## `term check`

{/* cite check-concepts-against-labels */}
{/* cite check-reference-fields-label-or-id */}
Check the set and every reference into it. `check` reads records, never prose.
It resolves each `concepts:` value against labels, ids and alt-labels, and
resolves `broader`, `narrower`, `related-terms` and `see` against labels and
ids. It reads each page's `graph:` block into the hierarchy, and reports what
does not line up. The twenty-two rules, their default severities and their
messages are on the [rules reference](/manni/term/reference/rules/).

```sh
manni term check [paths...] [options]
```

### Arguments

| Argument | Description |
|---|---|
| `[paths...]` | Files, directories, or globs to read, exactly as on [`list`](#term-list). |

### Options

| Option | Argument | Default | Description |
|---|---|---|---|
| `--as` | `<format>` | n/a | Input format for stdin. Required with `-`. |
| `--ext` | `<list>` | supported extensions | Comma-separated extensions kept when expanding directories and globs. |
| `--exclude` | `<glob>` | n/a | Glob to exclude. Repeatable. |
| `--collection` | `<name>` | every collection | Read one configured collection. Repeatable. |
| `--allow-empty` | n/a | off | Treat a missing path, no matched files or no terms as success. |
| `--no-gitignore` | n/a | on | Read files `.gitignore` covers as well. |
| `-c, --config` | `<path>` | discovered | Path to a config file. |
| `--no-color` | n/a | off | Disable colored output. |
| `-f, --format` | `<pretty\|json\|github\|sarif\|junit>` | `pretty` | Output format. The shapes are below. |
| `--baseline` | n/a | off | Compare against `.manni-term-baseline.json`, or the file config `baseline:` names. When the file does not exist yet, record this run's findings in it and exit `0`. After that, fail only on findings the file does not hold. Takes no value. |

### Output

{/* cite check-pretty-shape */}
`pretty` groups findings by file and line. Each row is the severity, the rule
id and the message. The summary counts each severity:

```
docs/guides/fitting.md:3
  warning manni:term/alt-label-reference   concepts: "PAL" is an alt-label of "progressive lens", so name the label.
  error  manni:term/undefined-term        concepts: "trifocal" names no entry.
docs/terms/bifocal.md:1
  notice manni:term/unused-term           no page's concepts: names this term
docs/terms/corrective-lens.md:5
  warning manni:term/asymmetric-hierarchy  narrower: omits "bifocal", which lists this entry as broader

1 error, 2 warnings, 1 notice in 3 terms
```

{/* cite check-clean-line */}
A clean run prints one line:

```
✓ 2 terms, 2 references, no findings
```

{/* cite check-json-shape */}
`json` prints `{ findings, summary }`. Each finding carries `rule`, `ruleId`,
`severity`, `message`, `file` and `line`, plus the entry's `id` when the
finding sits on an entry, and the `field` that breaks the rule when one does.
`summary` holds `terms`, `references`, `errors`,
`warnings` and `notices`, and `baseline` when one was read or written:

```json
{
  "findings": [
    {
      "rule": "unused-term",
      "ruleId": "manni:term/unused-term",
      "severity": "notice",
      "message": "no page's concepts: names this term",
      "file": "docs/terms/bifocal.md",
      "line": 1,
      "id": "bifocal"
    }
  ],
  "summary": {
    "terms": 3,
    "references": 2,
    "errors": 0,
    "warnings": 0,
    "notices": 1
  }
}
```

{/* cite github-escape-rule-id */}
`github` prints one workflow command per finding. The colon in the rule id is
escaped, because a workflow command reads `:` as a separator:

```
::warning file=docs/guides/fitting.md,line=3,title=manni%3Aterm/alt-label-reference::concepts: "PAL" is an alt-label of "progressive lens", so name the label.
::error file=docs/guides/fitting.md,line=3,title=manni%3Aterm/undefined-term::concepts: "trifocal" names no entry.
```

{/* cite sarif-rule-description */}
`sarif` and `junit` carry the same findings under the rule id
`manni:term/<rule>`, in the envelope, paths and fingerprints of the metadata
tool's [renderers](/manni/meta/reference/output-and-exit-codes/). Each message
is the finding's own. A SARIF rule's `shortDescription` is the rule's line from
the [rules reference](/manni/term/reference/rules/), and its `helpUri` is the
rule's section of that page:

```json
{
  "id": "manni:term/undefined-term",
  "shortDescription": {
    "text": "A page's concepts: names no entry, by label, id or alt-label."
  },
  "helpUri": "https://hawkeyexl.github.io/manni/term/reference/rules/#undefined-term"
}
```

```xml
<testcase name="docs/guides/fitting.md" classname="manni.term">
  <failure type="manni:term/undefined-term" message="concepts: &quot;trifocal&quot; names no entry. (line 3)"/>
</testcase>
```

{/* cite junit-one-testcase-per-file */}
{/* cite junit-classname */}
{/* cite sarif-vale-rule-no-helpuri */}
JUnit testcases carry the classname `manni.term`, one per file read. A `lint`
rule, `manni:term/prose/<Style.Rule>`, is Vale's, so its SARIF description
names the Vale rule and it has no `helpUri`.

### Baselines

`--baseline` is one flag for both halves of the ratchet.

```console
$ manni term check --baseline
✓ 1 finding recorded in .manni-term-baseline.json
$ manni term check --baseline
✓ 2 terms, 3 references, no findings, 1 baselined
```

{/* cite configured-baseline-missing */}
A configured [`baseline:`](/manni/term/reference/configuration/#keys) is
compared on every run, without the flag. When that file does not exist and the
flag is absent, the run stops with exit `2` and names the command that records
one.

### Exit codes

| Code | Meaning |
|---|---|
| `0` | No error-severity finding the baseline does not already hold. Warnings and notices never move the exit code. A run that records a baseline exits `0`. |
| `1` | At least one unbaselined error-severity finding. |
| `2` | Operational or usage error. See [usage errors](#usage-errors). |

## `term lint`

{/* cite lint-temp-file-per-field */}
{/* cite lint-vale-config */}
Run Vale over the definitions. Each entry's `definition`, `abstract` and
`scope-note` is written to a temporary file named `<id>.<field>.md`, and Vale
runs once over all of them. Vale reads its own configuration, or the file
[`tools.vale.config`](/manni/meta/reference/configuration/#tools) names. A
`[*.definition.md]` section in that configuration applies to definitions
alone.

```sh
manni term lint [paths...] [options]
```

### Arguments

| Argument | Description |
|---|---|
| `[paths...]` | Files, directories, or globs to read, exactly as on [`list`](#term-list). |

### Options

| Option | Argument | Default | Description |
|---|---|---|---|
| `--as` | `<format>` | n/a | Input format for stdin. Required with `-`. |
| `--ext` | `<list>` | supported extensions | Comma-separated extensions kept when expanding directories and globs. |
| `--exclude` | `<glob>` | n/a | Glob to exclude. Repeatable. |
| `--collection` | `<name>` | every collection | Read one configured collection. Repeatable. |
| `--allow-empty` | n/a | off | Treat a missing path, no matched files or no terms as success. |
| `--no-gitignore` | n/a | on | Read files `.gitignore` covers as well. |
| `-c, --config` | `<path>` | discovered | Path to a config file. |
| `--no-color` | n/a | off | Disable colored output. |
| `-f, --format` | `<pretty\|json\|github\|sarif\|junit>` | `pretty` | Output format. The same shapes as `check`. |

### Output

{/* cite lint-prose-rule-id */}
{/* cite lint-suggestion-is-notice */}
A finding sits on the source line of the field it came from. The rule id is
`manni:term/prose/<Style.Rule>`, keeping Vale's own rule name. Vale's
`suggestion` is reported as a notice:

```
docs/terms/kubernetes.md:7
  warning manni:term/prose/House.Simply   Drop 'Simply'.
docs/terms/kubernetes.md:11
  warning manni:term/prose/House.Simply   Drop 'just'.
docs/terms/progressive-lens.md:9
  error  manni:term/prose/House.Length   Keep a sentence under 20 words.

1 error, 2 warnings in 3 terms
```

{/* cite lint-block-source-lines */}
{/* cite lint-json-vale-fields */}
A literal `|` block keeps its lines, so a finding on its second line lands on
that source line. A folded `>-` block is one line once parsed, so its findings
sit on the field's first line. In `json` a finding also carries `tool: "vale"`,
`check` (Vale's rule name), `toolSeverity` (Vale's level) and `field`.

### Exit codes

| Code | Meaning |
|---|---|
| `0` | No error-severity alert. |
| `1` | At least one error-severity alert. |
| `2` | Vale is not on PATH, Vale could not run, or an operational or usage error. |

## `term write`

Write the set back, or render it elsewhere.

```sh
manni term write [paths...] [options]
```

{/* cite write-only-differing-files */}
{/* cite write-nothing-to-write */}
With no `-f`, each file's entries go back through the reader that read them.
Only an entry whose record differs from its file is rewritten, so a set that
has not changed leaves every file byte-identical and prints `Nothing to write`.

{/* cite write-shape-from-path */}
{/* cite write-dropped-fields-report */}
With `-f <format>` and `-o <path>`, the whole set is rendered into the path.
The path decides the shape. A trailing `/` or an existing directory gets one
entry per file, and anything else gets every entry in one file. A field the
target cannot hold is dropped, and the report says which fields, on how many
entries. [Move and hand off a
termbase](/manni/term/set-up/move-and-hand-off/#what-each-render-holds) has
every shape and what each keeps.

`-f tbx` writes TBX v2, and `-f tbx3` writes TBX v3. When every entry came from
one TBX file and `-f` names its version, the file's header and unchanged
entries are copied byte for byte. [Read the termbase
back](/manni/term/set-up/move-and-hand-off/#read-the-termbase-back) has what
each export keeps.

`-f skos` writes a SKOS concept scheme in JSON-LD, and `-f skos-ttl` writes the
same scheme in Turtle. Each id is one concept, carrying every language's
labels. A SKOS file is not rewritten in place, so `write` with no `-f` refuses
one.

{/* cite write-vale-asks-ls-config */}
`-f vale` writes a Vale style named `Terms`. Without `-o` it asks Vale where
its styles directory is. [Keep the terms and the docs in
step](/manni/term/set-up/#the-generated-style) has the files it writes.

<Aside type="caution" title="write writes by default">
`write` changes files unless you pass `--check` or `--dry-run`. Run it on a
clean working tree so the change is easy to review.
</Aside>

### Arguments

| Argument | Description |
|---|---|
| `[paths...]` | Files, directories, or globs to read, exactly as on [`list`](#term-list). An entry read from stdin has nowhere to be written back to, so `-` needs `-f` and `-o`. |

### Options

| Option | Argument | Default | Description |
|---|---|---|---|
| `--as` | `<format>` | n/a | Input format for stdin. Required with `-`. |
| `--ext` | `<list>` | supported extensions | Comma-separated extensions kept when expanding directories and globs. |
| `--exclude` | `<glob>` | n/a | Glob to exclude. Repeatable. |
| `--collection` | `<name>` | every collection | Read one configured collection. Repeatable. |
| `--allow-empty` | n/a | off | Treat a missing path, no matched files or no terms as success. |
| `--no-gitignore` | n/a | on | Read files `.gitignore` covers as well. |
| `-c, --config` | `<path>` | discovered | Path to a config file. |
| `--no-color` | n/a | off | Disable colored output. |
| `-f, --format` | `<format>` | each entry's own, in place | What to render: `markdown`, `mdx`, `asciidoc`, `rst`, `html`, `dita`, `docbook`, `tbx`, `tbx3`, `skos`, `skos-ttl`, `csv`, `json` or `vale`. |
| `-o, --out` | `<path>` | see below | The file or directory to render into. A trailing `/` means a directory. |
| `--check` | n/a | off | Write nothing. Exit `1` when the target differs from the render. |
| `--dry-run` | n/a | off | Write nothing. Print what would change, then the dropped and skipped lines a write prints, and exit `0`. |

`-o` depends on `-f`:

| `-f` | `-o` when omitted |
|---|---|
| none | each entry's own source, in place |
| `markdown`, `mdx`, `asciidoc`, `rst`, `html`, `dita`, `docbook` | required |
| `tbx`, `tbx3`, `skos`, `skos-ttl`, `csv`, `json` | required, and a file |
| `vale` | the styles directory `vale ls-config` reports |

### Output

{/* cite write-render-summary */}
{/* cite write-skipped-line */}
A render names the target and the number of entries written. A render into
one file per entry says so. Dropped fields follow on an indented line. An entry
the target construct could not read back is left out, and named on the line
after:

```
Wrote 3 terms to docs/terms/, one file each
```

```
Wrote 3 terms to build/glossary.xml
  dropped from a DocBook glossary: abstract on 1 term, hidden-labels on 1, scope-note on 1
```

```
Wrote 2 terms to glossary.md
  dropped from a definition list: abstract on 1 term, hidden-labels on 1, related-terms on 1, scope-note on 1
  skipped 1 term a definition list cannot read without a definition: varifocal
```

A Markdown or MDX definition list, an AsciiDoc `[glossary]` list, a
`.. glossary::` and an HTML `<dl>` skip an entry with no definition, such as a
`see` redirect.

A set in more than one language adds up to three lines. A one-file document
writes the first term's language, names the terms it left out, and counts
only the terms it wrote. A render that leaves a TBX file's header behind names
the file. A TBX render that joins two languages' differing `concept-entry`
keeps the first and says where:

```
Wrote 2 terms to build/glossary.md
  dropped from a definition list: hidden-labels on 1 term, concept-entry on 1, designations on 1
  dropped from a definition list: the header of glossary.tbx
  skipped 2 terms in another language than en: progressive-lens (de), bifocal (de)
```

```
Wrote 4 terms to build/terms.tbx
  kept the first language's value where languages differ: concept-entry.subject-field on 1 concept
```

A render into one file per entry puts each page under a directory named for
its language, `docs/terms/de/progressive-lens.md`, when the set holds more
than one.

{/* cite vale-style-file-counts */}
{/* cite vale-wiring-notice */}
`-f vale` lists each style file and what it holds. `Casing.yml`,
`Lowercase.yml` and `SentenceStart.yml` count the labels and alt-labels they
swap. When no section of Vale's configuration uses the `Terms` style, a notice
on stderr names the line to add. When the file has no section with
`BasedOnStyles`, the notice names a section to add instead:

```
Wrote 3 terms to .vale/styles/Terms
  Casing.yml      2 labels
  Lowercase.yml   3 labels
  Deprecated.yml  2 swaps
  PAL.yml         1 acronym
notice: no section of .vale.ini uses the Terms style. Add it to BasedOnStyles:
  [*.md]
  BasedOnStyles = Vale, Terms
```

```
notice: .vale.ini has no section with BasedOnStyles. Add one that uses the Terms style:
  [*.md]
  BasedOnStyles = Terms
```

{/* cite write-change-lines */}
{/* cite write-up-to-date-line */}
`--check` and `--dry-run` print each file that differs, with what would happen
to it: `would change`, `would be created` or `would be removed`. When nothing
differs a render prints that the target is up to date, and an in-place run
prints `Nothing to write`. `--dry-run` then prints the
dropped and skipped lines a write would:

```
.vale/styles/Terms/Deprecated.yml would change
```

```
.vale/styles/Terms is up to date
```

```
glossary.md would be created
  dropped from a definition list: abstract on 1 term, hidden-labels on 1, related-terms on 1, scope-note on 1
  skipped 1 term a definition list cannot read without a definition: varifocal
```

### Exit codes

| Code | Meaning |
|---|---|
| `0` | The set was written, or `--dry-run` printed what would change, or `--check` found the target up to date. |
| `1` | `--check` found a file that differs from the render. |
| `2` | Operational or usage error. See [usage errors](#usage-errors). |

### Examples

```sh
manni term write                                   # each entry back to its source
manni term write docs/glossary.xml -f markdown -o docs/terms/
manni term write docs/terms/ -f markdown -o glossary.md
manni term write -f tbx -o build/terms.tbx
manni term write glossary.tbx -f tbx3 -o build/glossary.tbx   # TBX v2 to v3
manni term write glossary.tbx -f markdown -o docs/terms/      # a page per term and language
manni term write vocab.ttl -f markdown -o docs/terms/         # a SKOS scheme as pages
manni term write -f skos-ttl -o build/terms.ttl               # the set as Turtle
manni term write -f vale                           # into Vale's styles directory
manni term write -f vale --check                   # keep the style in step
```

## `term fill`

Create a term page for each concept pages name and the termbase lacks, and
draft a definition for each entry that has none.

```sh
manni term fill [paths...] [options]
```

A concept is named by a page's `concepts:`, its `graph.concepts`, a section's
`concepts`, and the values of a `graph:` block's `broader`, `narrower` and
`related-concepts`. A block's own `label` is its page naming itself, so it
never asks for a page. A name that matches a term's label, id or alt-label,
ignoring case, already has a page. `fill` never overwrites a value a person
wrote, and never replaces a file that is already there.

A new page carries what the pages say about it. Its alt-labels come from the
`graph:` blocks labelled with the concept. Its `broader`, `narrower` and
`related-terms` are the union of those blocks' edges. Its `language` is the
naming page's, when that page has one. A block's `definition` is carried over
as written, with no model involved:

```yaml title="docs/glossary/retry.md"
---
title: Retry
type: term
id: retry
language: en
label: Retry
definition: Sending a failed request again after it timed out or returned 5xx.
alt-labels:
  - Retries
broader:
  - Errors
related-terms:
  - Backoff
meta-provenance:
  - generated-by: claude-sonnet-5-5
    fields:
      - /definition
    confidence:
      /definition: 0.86
---
```

When a provider resolves, a model drafts each missing definition. A draft
under the confidence threshold leaves a new page as a stub and an existing
entry unchanged. A draft that clears it is written and recorded in the page's
`meta-provenance`, under the model's name. With no provider, a new page is a
stub with no definition. `--offline` sends nothing off this machine. It runs
`llama-cpp` as `--local` does, and only with a model already downloaded, so
with none on disk new pages are stubs too. Only a term page can be
filled in place. An entry in a manifest, a TBX file or a glossary construct is
reported as skipped.

`--crawl` also sends each page's body to the model, in chunks of
`--chunk-chars`. The model proposes the terms the page uses, each with
alt-labels, a definition from context and a confidence. Each `keywords:` value
joins them. Candidates merge across pages by label, ignoring case. One gets a
page when it appears on at least `term.fill.crawl.minPages` pages and its
confidence clears the threshold. A keyword no model proposed gets a drafted
definition, which the same threshold decides.

New pages go in the first of these that is set:

1. `-o, --out`.
2. `term.fill.out`.
3. The one directory every existing term page shares.

When none applies, `fill` refuses. A page is named `<id><ext>`, where the id is
the slug of the label. The extension is the one most term pages in that
directory use. When there are none, it is the most common page extension in
the run, and `.md` when that finds nothing either.

<Aside type="caution" title="fill writes by default">
`fill` creates and changes files unless you pass `--dry-run`. Run it on a
clean working tree so the change is easy to review.
</Aside>

### Arguments

| Argument | Description |
|---|---|
| `[paths...]` | Files, directories, or globs to read, exactly as on [`list`](#term-list). With none, the configured collections and `term.manifests` are read. |

### Options

| Option | Argument | Default | Description |
|---|---|---|---|
| `--as` | `<format>` | n/a | Input format for stdin. Required with `-`. |
| `--ext` | `<list>` | supported extensions | Comma-separated extensions kept when expanding directories and globs. |
| `--exclude` | `<glob>` | n/a | Glob to exclude. Repeatable. |
| `--collection` | `<name>` | every collection | Read one configured collection. Repeatable. |
| `--allow-empty` | n/a | off | Treat a missing path or no matched files as success. A run with no terms is always allowed. |
| `--no-gitignore` | n/a | on | Read files `.gitignore` covers as well. |
| `-c, --config` | `<path>` | discovered | Path to a config file. |
| `--no-color` | n/a | off | Disable colored output. |
| `-o, --out` | `<dir>` | `term.fill.out`, else detected | The directory new term pages go in. |
| `--crawl` | n/a | off | Also ask the model for the terms page bodies and `keywords:` use. Needs a model, and under `--offline` one already downloaded. |
| `--offline` | n/a | off | No network egress. Inference runs on this machine with `llama-cpp`, and only with a model already downloaded. A configured hosted provider is set aside with a note, and a hosted `--provider` is a usage error. Nothing is downloaded. With no model on disk, new pages are stubs and existing entries are left alone. |
| `--provider` | `<name>` | `term.provider`, else `providers:`, else `auto` | `auto`, `anthropic`, `openai`, `claude-cli` or `llama-cpp`. |
| `--model` | `<model>` | `term.model`, else `providers:` | The model. Needs a named provider, from the flag or config. |
| `--local` | n/a | off | Run inference on this machine with `llama-cpp`, over any configured provider. |
| `--confidence` | `<n>` | `term.fill.confidenceThreshold`, else `0.7` | The confidence, from 0 to 1, a definition or a crawl candidate must reach. |
| `--max-turns` | `<n>` | `term.fill.maxTurns`, else unbounded | Stop after this many inference calls. A cached answer costs none. |
| `--chunk-chars` | `<n>` | `12000` | Characters of a page sent per call under `--crawl`. |
| `--no-cache` | n/a | on | Ask the model again rather than reuse an answer from `term.fill.cacheDir`. |
| `--dry-run` | n/a | off | Write nothing. Print what would happen. |
| `-f, --format` | `<pretty\|json>` | `pretty` | Output format. |

### Output

One line per entry names what happened, the file, the label and the
definition. A summary line follows:

```
created docs/glossary/retry.md     Retry     stub, no definition
created docs/glossary/backoff.md   Backoff   definition from graph: block
filled  docs/glossary/jitter.md    Jitter    definition drafted (0.91)
skipped docs/glossary/quorum.md    Quorum    confidence 0.41 is under 0.7
2 terms created, 1 filled, 2 left without a definition, 1 skipped
```

The first word is `created`, `filled`, `skipped` or `exists`. Under
`--dry-run` a write reads `would create` or `would fill`, and the summary says
`would be created`. A new page whose draft is under the threshold reads
`stub, confidence 0.41 is under 0.7`. An entry the turn budget did not reach
reads `turn budget`, and a run picks it up again once the budget allows.

`-f json` prints the same report:

```json
{
  "entries": [
    {
      "action": "create",
      "file": "docs/glossary/idempotency-key.md",
      "id": "idempotency-key",
      "label": "Idempotency key",
      "language": "en",
      "source": "crawl",
      "from": ["docs/api/retries.md:41", "docs/api/payments.md:12"],
      "definition": { "status": "drafted", "confidence": 0.88, "model": "anthropic/claude-sonnet-5-5" }
    }
  ],
  "summary": { "created": 1, "filled": 0, "skipped": 0, "withoutDefinition": 0, "turns": 14 }
}
```

| Field | Values |
|---|---|
| `action` | `create`, `fill`, `skip` or `exists`. |
| `source` | `metadata` for a name a page's metadata holds, `crawl` for a term the crawl found. |
| `from` | Each place that named it, as `file:line`, or `file` when the line is unknown. |
| `definition.status` | `drafted`, `carried`, `missing` or `below-threshold`. |
| `definition.confidence`, `definition.model` | Present when a model answered. |
| `reason` | Present on a `skip` that a confidence does not explain: `turn budget`, or `not a term page`. |
| `summary.withoutDefinition` | Pages created, and entries skipped, that have no definition after the run. |
| `summary.turns` | The inference calls the run made. |

When no provider resolves, a warning goes to stderr and the run goes on with
stubs. A provider named in config or on the command line that cannot run says
why first:

```
manni: the configured provider "anthropic" could not run: Anthropic provider needs ANTHROPIC_API_KEY set (or choose another provider)
manni: no model provider is configured, so new terms have no definition; pass --provider or --local.
```

Under `--offline` with no model on disk, the warning says so:

```
manni: no model is available offline, so new terms have no definition; download one first with --local, or drop --offline.
```

### Exit codes

| Code | Meaning |
|---|---|
| `0` | Every page that could be written was written, or `--dry-run` printed what would be. |
| `2` | Operational or usage error. See [usage errors](#usage-errors). |

### Examples

```sh
manni term fill --offline --dry-run           # what is missing, nothing sent
manni term fill --offline                     # local drafts, or stubs with no model on disk
manni term fill                               # pages, and drafted definitions
manni term fill --crawl -o docs/glossary/     # terms no metadata named
manni term fill --dry-run -f json             # for a script
manni term fill docs/ -o docs/glossary/ --crawl --provider anthropic --model claude-sonnet-5-5 \
  --confidence 0.8 --max-turns 40 --chunk-chars 8000 --no-cache --dry-run -f json
```

## Usage errors

{/* cite usage-errors-stderr-exit-2 */}
Every usage error goes to stderr, prefixed `manni:`, and exits `2`. Nothing is
written.

| Invocation | stderr |
|---|---|

| `term check -` with no `--as` | `manni: reading stdin needs --as <format>.` |
