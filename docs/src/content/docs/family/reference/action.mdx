{/* cite action-is-a-composite-around-the-npm-package */}
The packaged Action runs the same npm package the CLI does. It sets up Node,
fetches `manni`, and shells out to one manni command. Nothing it does is
unavailable from the CLI. It exists so the invocation lives in one place,
instead of being copy-pasted into every repository that wants it.

{/* cite action-runs-check-by-default */}
The Action runs [`manni check`](/manni/family/check/) unless told otherwise.
That is every check the repository has set up, as one gate.

```yaml
- uses: actions/checkout@v7
  with:
    fetch-depth: 0
- uses: hawkeyexl/manni@v4
```

## Inputs

{/* cite action-every-input-is-optional */}
Every input is optional. An input left unset contributes nothing to the command
line, and it does not become an empty flag.

| Input | Default | Maps to |
|---|---|---|
| `command` | `check` | The words after `manni`, such as `meta validate` or `cite check`. Split on whitespace and never run through a shell. Empty means `check`. |
| `paths` | none | Positional paths after the command. Files, directories, or globs. Space-separated, or one per line. Use lines for any path containing a space. Unset, the command reads the [collections](/manni/meta/reference/configuration/#collections) in your config. |
| `schema` | none | One `-s` per line, for a command that takes `-s`, such as `meta validate`. |
| `config` | none | `-c` |
| `format` | `github` | `--format`. An empty string passes no `--format`, for a command that has none. |
| `output-file` | none | Sends the command's stdout to this file, relative to the workspace. Its directory is created when missing. stderr stays in the job log. |
| `version` | `latest` | The npm version range fetched, as `@hawkeyexl/manni@<version>`. Also accepts a path or tarball. `check` needs 4.4.0 or newer. |
| `args` | none | Appended verbatim after everything else, for anything the inputs above do not cover. [`--collection`](#selecting-a-collection) reaches the Action this way. |
| `node-version` | `24` | Passed to `actions/setup-node`. manni needs 24 or newer. |

{/* cite action-builds-the-argv */}
The Action runs the command words, then the paths, each `-s`, `-c`, `--format`
and `args`, in that order. It logs that line before the run, with ` > <file>`
when `output-file` is set:

```text
manni meta validate docs/ guides/my\ notes/ -s ./schemas/page.schema.json --format sarif > reports/manni.sarif
```

{/* cite action-stdin-is-dev-null */}
manni reads its stdin from `/dev/null`. `manni check` reads stdin for a Claude
Code hook, so the redirect keeps a CI run from waiting on the runner's pipe.

<Aside type="caution" title="Quotes are not shell-processed">
`paths` and `args` accept several values either space-separated on one line or
**one per line**. On a single line the value is split on whitespace only, and
shell quoting is not interpreted. So `args: --exclude "*.draft.md"` reaches
manni with the quote marks still inside the pattern, and the exclusion
silently matches nothing.

Use one item per line whenever a value contains a space. The Action emits a
workflow warning if it sees a quote character in a single-line value.

```yaml
- uses: hawkeyexl/manni@v4
  with:
    command: meta validate
    paths: |
      docs/**/*.md
      guides/my notes/*.mdx
    args: |
      --exclude
      *.draft.md
```
</Aside>

### Globs reach manni unexpanded

{/* cite action-globs-are-not-shell-expanded */}
A `paths` value like `docs/**/*.md` is passed through as that string. The Action
disables shell globbing deliberately. manni applies its own extension
filtering and [gitignore rules](/manni/meta/reference/cli/#shared-input-model).
Letting the runner expand the pattern first would substitute the shell's view of
the tree for manni's. It would do so silently, and differently depending on
the working directory.

### Selecting a collection

{/* cite action-args-is-the-escape-hatch */}
There is no `collection` input. `--collection` reaches the Action through `args`,
the documented escape hatch for every flag the inputs above do not name. It is a
`meta validate` flag, so the step names that command:

```yaml
- uses: hawkeyexl/manni@v4
  with:
    command: meta validate
    args: --collection guides
```

{/* cite action-collection-repeats-rather-than-splitting */}
The flag repeats rather than splitting on commas, so two collections are two
occurrences on the same line:

```yaml
- uses: hawkeyexl/manni@v4
  with:
    command: meta validate
    args: --collection guides --collection blog
```

{/* cite action-collection-cannot-be-combined-with-paths */}
Leave `paths` unset when you do this. `--collection` selects from the config, so
it cannot be combined with positional paths. A workflow that sets both fails the
step with exit 2. The message is
`--collection selects a configured collection; it cannot be combined with paths.`
With neither, the run covers every declared collection, which is what the
`paths`-less form above already did.

## Run every check

With no inputs, the Action runs `manni check --format github`. Every check the
repository has set up reports its findings as annotations on the pull request.
A clean run exits 0.

```yaml
- uses: hawkeyexl/manni@v4
```

```text
manni check --format github
```

A finding at error level fails the step with exit 1. Here `docs/limits.md`
lacks a `description`, and the annotation lands on the page:

```text
manni check --format github
::error file=docs/limits.md,line=1::[manni:core:1.0.0] (root) must have required property 'description'
```

The checkout needs `fetch-depth: 0` when the repository has citations.
`manni cite check` reads the commit each pin was minted at, and a shallow clone
cannot supply it. [Gate every check a repo has set up](/manni/family/check/)
says what puts a domain in the gate.

## Run one command

`command` picks any other manni command. This runs the citation check alone:

```yaml
- uses: hawkeyexl/manni@v4
  with:
    command: cite check
    paths: docs/
```

```text
manni cite check docs/ --format github
```

`command: meta validate` runs the metadata check alone, as the Action did
before it ran `check`. These inputs run the same command line as then:

```yaml
- uses: hawkeyexl/manni@v4
  with:
    command: meta validate
    paths: "docs/**/*.md"
    schema: ./schemas/page.schema.json
```

```text
manni meta validate docs/\*\*/\*.md -s ./schemas/page.schema.json --format github
```

A command with no `--format` option needs `format: ""`, or it fails on the
default `github`:

```yaml
- uses: hawkeyexl/manni@v4
  with:
    command: site build
    format: ""
```

```text
manni site build
```

`command: status` runs [`manni status`](/manni/family/reference/cli/#status),
which takes `pretty` or `json`. So set `format` to one of those, or to `""`.
It gates nothing, and exits 0 whatever the report says.

### When the command is wrong

The Action does not judge `command`. manni does, with its own message and exit
2, so the step fails and `exit-code` is `2`.

| Workflow | Printed | Exit |
|---|---|---|
| `command: lint chek` | `error: unknown command 'chek'` then `(Did you mean check?)` | 2 |
| `command: validate` | `error: unknown command 'validate'` then ``(`validate` is a metadata command: try `manni meta validate`)`` | 2 |
| `command: check` with `schema` | `error: unknown option '-s'` | 2 |
| `command: site build`, `format` left at `github` | `error: unknown option '--format'` | 2 |
| `command: check`, `format: junit` | `error: option '-f, --format <format>' argument 'junit' is invalid. Allowed choices are pretty, json, github, sarif.` | 2 |
| `command: check`, no config | `manni: No manni.config.yaml found from <workspace> up to the repository root. Create one there with a collections: entry for your docs.` | 2 |
| `command: check`, nothing set up | `manni: Nothing is set up to check in manni.config.yaml. Run manni status to see what each domain needs.` | 2 |
| `version: "4.3"`, `command` unset | `error: unknown command 'check'` | 2 |

## Upload SARIF to code scanning

`format: sarif` with `output-file` writes one SARIF log that
`github/codeql-action/upload-sarif` can read. Without `output-file` the log
lands in the job log, where the upload cannot reach it.

```yaml title=".github/workflows/docs.yml"
jobs:
  manni:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      security-events: write   # upload-sarif needs it; without it the upload is a 403
    steps:
      - uses: actions/checkout@v7
        with:
          fetch-depth: 0
      - id: manni
        uses: hawkeyexl/manni@v4
        with:
          format: sarif
          output-file: manni.sarif
      - if: ${{ !cancelled() && hashFiles('manni.sarif') != '' }}
        uses: github/codeql-action/upload-sarif@v3
        with:
          sarif_file: manni.sarif
```

The manni step still fails the job on exit 1 or 2. The upload runs anyway,
because `!cancelled()` replaces the default `success()` condition.

Leave `category` unset. `manni check -f sarif` gives each domain its own
`manni/<domain>/` category, and a last `manni/check/` run names what was
skipped.

{/* cite action-removes-an-empty-output-file */}
When manni fails before printing anything, the Action removes the empty file,
and `hashFiles` skips the upload. `upload-sarif` rejects a zero-byte log.

{/* cite action-warns-on-the-github-format-to-a-file */}
The `github` format is workflow commands, which annotate only from the job log.
So `output-file` with `format: github` prints a warning and runs on:

```text
::warning::output-file sends the github format's workflow commands to <path>, so no annotations appear. Pick another format to write a file.
```

## Outputs

| Output | Value |
|---|---|
| `exit-code` | manni's exit code. `0` clean, `1` an error-level finding, `2` the command could not run or was not a valid manni command. |

{/* cite action-exit-code-needs-continue-on-error */}
`exit-code` is only observable with `continue-on-error: true`. Without it a
non-zero code has already failed the step, so there is nothing left to read:

```yaml
- id: manni
  uses: hawkeyexl/manni@v4
  continue-on-error: true
  with:
    format: json
    output-file: manni.json
- run: jq -r '.checks[] | "\(.status) \(.command)"' manni.json
- if: steps.manni.outputs.exit-code == '1'
  run: echo "Findings, but not blocking this job."
```

<Aside type="note" title="Why there is no flag-per-input">
The Action deliberately stops at nine inputs. Enumerating every CLI flag would
create a second command surface to keep in step with the first, and `args` already
reaches anything not listed. `command` and `output-file` are not CLI flags. They
pick the words after `manni` and where its stdout goes. The inputs that do exist
are checked against `action.yml` by `npm run docs:check-action`, so this table
cannot drift from the Action itself.
</Aside>

## Versioning

{/* cite action-major-tag-moves-on-each-release */}
`@vN` is a moving tag. On each stable release, the release job moves it to the
newest release of that major.

Pin a full tag such as `uses: hawkeyexl/manni@v4.15.0` instead when you want an
immutable Action. That is the usual trade between getting fixes automatically
and knowing exactly what runs.

{/* cite action-version-input-picks-the-cli */}
The Action tag chooses the Action's code. The `version` input chooses the CLI
it runs, and defaults to `latest`, the newest published CLI. Set `version` to a
major such as `2`, or to an exact version, when you want a reproducible CLI.

## The equivalent by hand

{/* cite action-hand-written-form-still-supported */}
The Action replaces this, which remains supported. For the metadata check alone,
[`examples/manni.yml`](https://github.com/hawkeyexl/manni/blob/main/examples/manni.yml)
shows the same steps with `meta validate`:

```yaml
- uses: actions/checkout@v7
  with:
    fetch-depth: 0
- uses: actions/setup-node@v6
  with:
    node-version: 24
- run: npx -y @hawkeyexl/manni check --format github < /dev/null
```

{/* cite action-wraps-node-setup-and-the-cli-call */}
Use the hand-written form on a runner that cannot use a composite action, or
when you need to control the Node setup yourself. Everything else moves inside
the Action, including the CLI version it fetches, the `--format github` default,
and the Node version. So changing the recommended invocation is a tag move, rather than an
edit in every repository.
