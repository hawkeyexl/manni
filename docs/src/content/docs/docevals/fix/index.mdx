You did not configure this check and you do not need to learn the tool. Start with the table.

**manni docevals** runs quality checks, called **evals**, against documentation pages. Each eval is one
assertion about a page, decided either by a script or by an AI judge.

## Which failure is this?

Find your CI output in the left column.

| What you see | What it is | What to do |
|---|---|---|
| A message with a **file and line**, like `error:14 [regex/found] …` | A script-based check | [Fix the line](#a-finding-with-a-line) |
| A line starting **`AI judge: fail`**, then `Observed:` and `Reasoning:` | An AI verdict | [Read the assertion](#an-ai-verdict) |
| **`needs-review`**, `Awaiting human review`, or `AI judge: no confident verdict` | Waiting on a person | [Not yours to fix](#needs-review) |
| An **assertion changed since its script was generated** | A generated script is out of date | [Not yours to fix](#stale-generated-script) |
| **Exit code 2**, or "could not run" / missing key / bad config | The tool itself failed | [Not your fault](#exit-2) |

The distinction that matters most is this. **Exit 1 means a docs problem, exit 2 means a pipeline problem.**
If you are looking at exit 2, stop and tell whoever owns CI.

## A finding with a line

```text
docs/actions/goTo.mdx
  FAIL no-todo-markers  docs/actions/goTo.mdx:7
       error:14 [regex/found] Pattern /\b(TODO|TBD|FIXME)\b/ found in body, expected absent. Remove or reword the matching text.
       docs/actions/goTo.mdx no-todo-markers: The page carries no TODO, TBD or FIXME markers.
       Guide: https://hawkeyexl.github.io/manni/docevals/fix/
```

Read the finding as `severity:line [rule] message`. A script found something specific at line 14,
and the message ends with what to do about it.

The two lines under it say what the eval asks for. The first names the file that declares the
eval, the eval's name, and its assertion. The second links this page. `docs/actions/goTo.mdx:7`
on the `FAIL` line is the same declaration, by line.

- Go to that line and make the change the message describes, then
  [re-run that one eval locally](#re-run-only-the-eval-that-failed) before you push.
- The rule says what the pattern check wanted:

  | Rule | Meaning |
  |---|---|
  | `regex/found` | The page contains text it must not. The line is the first match. |
  | `regex/not-found` | The page lacks text it must contain. |
  | `regex/count` | The text appears a different number of times than required. |
  | `regex/unreadable-target` | The check could not read the part of the page it targets. Ask whoever owns the eval. |

- A message starting `Exit code` has no rule. It comes from a command check. The sentence after
  the code says what to do, and the command's own output follows `Output:`.
- A message starting `Command timed out`, `Failed to run command` or `No command to run` is about
  the eval, not your page. Tell whoever owns the eval.

Only `error` fails the build. If your message says `warning` or `notice`, that check is not what turned
the build red. Keep reading the log.

## An AI verdict

An example of a judged failure, as the default report prints it:

```text
  FAIL no-future-promises [auto-fail]  docs/actions/goTo.mdx:5
       AI judge: fail (confidence 0.91). Edit the page so the assertion holds.
       Observed: Waiting for network idle is planned for a later release.
       Reasoning: Line 16 promises a later release.
       votes pass:0 fail:3 partial:0
       docs/actions/goTo.mdx no-future-promises: The page makes no claims about unreleased or future functionality.
       Guide: https://hawkeyexl.github.io/manni/docevals/fix/
```

The judgement is about the page rather than a character position. So the line is the one that
declares the eval, in the page's frontmatter or in the manifest that holds its evals.

Read it from the top:

- **`Observed`** quotes the text the judge based its verdict on. Search the page for it.
- **`Reasoning`** says why that text breaks the eval. Both come from a run that did not pass.
- **The guidance line** is the assertion, what the page was required to do.

The quote tells you where the problem is, and the assertion tells you what was required. To see
every eval that applies to the page, each with its assertion:

```bash
npx @hawkeyexl/manni docevals list docs/actions/goTo.mdx
```

For the eval's examples, find the named eval, here `no-future-promises`, in `manni.config.yaml`,
or inline in the page's own frontmatter. It looks like this:

```yaml
  no-future-promises:
    assertion: The page makes no claims about unreleased or future functionality.
    examples:
      pass: Describes only shipped behavior.
      fail: Says "coming soon" or references an unreleased version.
```

The `examples.fail` line is the useful one. It shows what violating this looks like. Between the
`Observed` quote and that example, the offending sentence is usually obvious.

If you genuinely disagree with the verdict, that is a conversation with whoever owns the eval, not a
thing to work around. Say so in the pull request.

## `needs-review`

The judge was not confident enough either way, so the eval is waiting on a person. The report
says so in one of two lines:

```text
AI judge: no confident verdict (confidence 0.55). Record a verdict with manni docevals review, or sharpen the assertion and run manni docevals calibrate.
Awaiting human review. Record a verdict with manni docevals review.
```

The first comes from a judged eval, with `Observed:` and `Reasoning:` under it. The second comes
from a `human` eval, which no judge sees.

**You cannot resolve this yourself.** It needs someone with standing to record a verdict. Ask
whoever owns the docs quality checks in your repo; the command they run is
`manni docevals review <file> <eval> pass|fail`.

This is a legitimate outcome, not you having done something wrong.

## Stale generated script

Some checks are scripts generated from a plain-language assertion. If someone edited the assertion
without regenerating, the script no longer matches it.

Not yours to fix unless you were the one who edited the assertion. In that case, regenerate:

```bash
npx @hawkeyexl/manni docevals generate <the file>
```

and commit the updated script alongside your change.

## Exit 2

Bad config, a missing provider key, a malformed flag, or a run that would have checked nothing.
**This is not a docs problem and not your fault.** Tell whoever owns the pipeline. Re-running the
job will not help.

`No evals resolved` is the one worth naming, because it looks like the tool is complaining about
your pages. It is not. Nothing in the config attaches an eval to any page the run would check. The job stopped
rather than reporting success over an empty report. That is a
configuration fix, not a content fix.

## Reproduce it locally

CI had a provider key and a warm cache; your laptop has neither. A naive local run either fails on a
missing credential or costs money.

Run the deterministic checks on just your file:

```bash
npx @hawkeyexl/manni docevals run docs/your-page.mdx --deterministic-only
```

No API key needed, no cost. This covers everything except AI verdicts.

### Re-run only the eval that failed

Your CI output names the eval. Hand that name to `--eval` and nothing else runs:

```bash
npx @hawkeyexl/manni docevals run docs/your-page.mdx --deterministic-only --eval no-todo-markers
```

Seconds instead of a whole pass, and the output is the one check you are trying to fix. Repeat after
each edit until it goes green.

Two things about that output:

- **The `Suites` lines will say `partial — filtered run, target not evaluated`.** That is not a
  failure. A filtered run only measured part of the suite, so it prints the numbers and withholds
  the verdict. Read the eval lines above it; those are yours.
- **A name that matches nothing is exit 2, not a clean run.** `matched no evals` means you mistyped
  the name, or that eval does not apply to this page. Check with `list`, below.

Because it never reports a suite as meeting its target, `--eval` is a debugging aid and not a
replacement for the real check. Push and let CI run everything.

To see what applies to a page without running anything:

```bash
npx @hawkeyexl/manni docevals list docs/your-page.mdx
```

Exit `0` means clean.
