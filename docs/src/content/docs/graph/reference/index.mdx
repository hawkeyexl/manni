## The three contracts

Three files decide what manni graph accepts and produces, and each is versioned
and immutable once published.

**The page vocabulary**, `manni:graph:1.0.0`. What a `graph:` block
may contain. There is no `graph validate`. A `graph:` block is frontmatter, so
`manni meta validate` checks it against this vocabulary. See
[Checking a `graph:` block](/manni/graph/reference/cli/#checking-a-graph-block). The
vocabulary is bundled into the build, so the published package never reads a
file from the repository it was built in.

**The shapes**, `shapes/graph/shapes-1.0.0.ttl`. What the built graph must look
like, validated by `manni graph check`. They ship in the npm package because
`check` reads them at run time. They are closed, so a predicate they have not
learned fails.

**The namespace**, `https://hawkeyexl.github.io/manni/graph/ns#`. The terms the
emitter mints that no standard vocabulary covers. The IRI dereferences to a
document defining every one of them. That is why it is this IRI rather than a
host serving a 404. The custom set stays deliberately small: a Dublin Core,
SKOS, PROV, schema.org, FOAF or iiRDS term is preferred wherever one exists.
