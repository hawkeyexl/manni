manni docs exposes three verbs, [`start`](#docs-start), [`build`](#docs-build)
and [`preview`](#docs-preview). Each one finds the site, detects its framework,
and runs the framework's own command with inherited stdio. `docs` has no
default subcommand. A bare `manni docs` prints usage and exits `2`.

```sh
manni docs [options] <command> [command options] [dir] [-- <args...>]
```

## Global options

Global options are accepted before the subcommand.

| Option | Description |
|---|---|
| `-V, --version` | Print the manni version and exit. |
| `-h, --help` | Print help for the program or a subcommand. |

## `docs`

Start, build and preview the docs site. Every command on this page lives under
it. `docs` accepts its own `-V, --version`, which reports the manni version,
and `-h, --help`. Run with no subcommand it prints usage, exit `2`.

```sh
manni docs [options] <command> [command options] [dir] [-- <args...>]
```

## `docs start`

Run the framework's dev server, with hot reload, until Ctrl-C or SIGTERM stops
it. A stop by signal exits `0`.

```sh
manni docs start [dir] [options] [-- <args...>]
```

### Arguments

| Argument | Required | Description |
|---|---|---|
| `[dir]` | no | The site's directory. Omitted: `docs.dir`, else [found by search](#how-the-site-is-found). One directory, not a list. |

### Options

| Option | Argument | Default | Description |
|---|---|---|---|
| `--port` | `<n>` | none | The port, an integer from 1 to 65535. Without it, the port of a local collection `url:`, else the framework's default. See [the port and host](#the-port-and-host). |
| `--host` | `<host>` | none | The host to bind. Without it, the host of a local collection `url:`, else the framework's default. Refused for Mintlify and Fern, whose dev servers take no host. |
| `-c, --config` | `<file>` | discovered | Path to a manni config file. |

## `docs build`

Run the framework's production build once. A build that fails exits `2`, and
the framework's own output above the last line says why. Mintlify and Fern
have no local build, so `build` stops with exit `2` there. `build` takes no
`--port` or `--host`, because nothing is served.

```sh
manni docs build [dir] [options] [-- <args...>]
```

### Arguments

| Argument | Required | Description |
|---|---|---|
| `[dir]` | no | The site's directory. Omitted: `docs.dir`, else [found by search](#how-the-site-is-found). |

### Options

| Option | Argument | Default | Description |
|---|---|---|---|
| `-c, --config` | `<file>` | discovered | Path to a manni config file. |

## `docs preview`

Run `build`, then serve the output until Ctrl-C or SIGTERM stops it. It always
builds first, so it never serves stale output. A build that fails exits `2`
before anything is served. The serve step is the framework's own preview
command, or the [built-in server](#the-built-in-server) for a framework that
has none.

```sh
manni docs preview [dir] [options] [-- <args...>]
```

### Arguments

| Argument | Required | Description |
|---|---|---|
| `[dir]` | no | The site's directory. Omitted: `docs.dir`, else [found by search](#how-the-site-is-found). |

### Options

| Option | Argument | Default | Description |
|---|---|---|---|
| `--port` | `<n>` | none | The port the output is served on, an integer from 1 to 65535. Without it, the port of a local collection `url:`, else the framework's default. |
| `--host` | `<host>` | none | The host the output is served on. Without it, the host of a local collection `url:`, else the framework's default. |
| `-c, --config` | `<file>` | discovered | Path to a manni config file. |

## Arguments after `--`

Everything after `--` is appended verbatim to the command manni runs, after
npm's own `--` where one is needed. The arguments are space-separated, because
they are argv. Under `preview` they go to the serve step, not the build. A
build's flags belong in [`docs.commands.build`](#configuration). The
[built-in server](#the-built-in-server) takes no arguments, so `preview` with
arguments after `--` is refused there, exit `2`.

```console
$ manni docs preview -- --open
manni: Starlight in docs/. Running npm run build
manni: Starlight in docs/. Running npm run preview -- --host 127.0.0.1 --port 4321 --open
```

There is no `-f, --format`. These verbs print no report, so the framework's
own output is the output.

## How the site is found

1. `[dir]` when it is given.
2. Else `docs.dir`, resolved against the config file's directory.
3. Else a search, where the first match wins. It looks in the config file's
   directory, or the working directory when there is no config. Then it looks
   in that directory's `docs/`, `website/` and `site/`.

In a directory, the markers in the [framework table](#frameworks) decide the
framework. Fern is the exception to "in a directory". Its marker is
`fern/fern.config.json`, and the site's directory is the parent of `fern/`.
Two frameworks in one directory are refused, exit `2`. A `[dir]` with no
marker is refused too, unless `docs.commands` sets every command the verb
needs.

## Frameworks

| Framework | Marker | start | build | preview | Port / host flags | Default port |
|---|---|---|---|---|---|---|
| Mintlify | `mint.json`, or `docs.json` with Mintlify's `$schema` or `theme` | `mint dev` | none | none | `--port` / none | 3000 |
| Fern | `fern/fern.config.json` | `fern docs dev` | none | none | `--port` / none | 3000 |
| Starlight | an `@astrojs/starlight` dependency | `dev`, else `astro dev` | `build`, else `astro build` | `preview`, else `astro preview` | `--port` / `--host` | 4321 |
| Docusaurus | an `@docusaurus/core` dependency | `start`, else `docusaurus start` | `build` | `serve`, else `docusaurus serve` | `--port` / `--host` | 3000 |
| VitePress | a `vitepress` dependency | `docs:dev`, else `vitepress dev <root>` | `docs:build` | `docs:preview` | `--port` / `--host` | 5173 |
| Nextra | a `nextra` dependency | `dev`, else `next dev` | `build` | `start`, else `next start` | `--port` / `--hostname` | 3000 |
| Fumadocs | a `fumadocs-core` dependency | `dev`, else `next dev` | `build` | `start`, else `next start` | `--port` / `--hostname` | 3000 |
| Rspress | an `rspress` or `@rspress/core` dependency | `dev`, else `rspress dev` | `build` | `preview` | `--port` / `--host` | 3000 |
| MkDocs | `mkdocs.yml` | `mkdocs serve` | `mkdocs build` | the built-in server over `site/` | `-a host:port` | 8000 |
| Zensical | `zensical.toml`, or `mkdocs.yml` with `zensical` in the requirements or `pyproject.toml` | `zensical serve` | `zensical build` | the built-in server over `site/` | `-a host:port` | 8000 |
| Sphinx | `conf.py` or `source/conf.py` | `sphinx-autobuild <src> <src>/_build/html` | `sphinx-build -M html <src> <src>/_build` | the built-in server over `_build/html` | `--port` / `--host` | 8000 |
| Hugo | `hugo.toml`, `hugo.yaml` or `hugo.json` | `hugo server` | `hugo` | the built-in server over `public/` | `--port` / `--bind` | 1313 |
| Jekyll | `_config.yml`, with a Gemfile naming `jekyll` or `github-pages` | `jekyll serve` | `jekyll build` | the built-in server over `_site/` | `--port` / `--host` | 4000 |

A dependency counts in `dependencies` or `devDependencies` of the site
directory's `package.json`.

- **A script, else a binary.** Where a cell names a script and then a binary,
  the script runs when `package.json` has it, as `npm run dev`. It carries the
  project's own flags. Otherwise the binary runs through the package manager.
- **The package manager.** The `packageManager` field of `package.json` names
  it. Without one, the lockfile found walking up to the git root does. Without
  either, it is npm.
- **Python and Ruby.** MkDocs, Zensical and Sphinx run under `uv run` when a
  `uv.lock` is present, or `poetry run` for a `poetry.lock`. Jekyll runs under
  `bundle exec`.
- **Output directories.** The built-in server reads the framework's default
  output directory. A custom `site_dir` or `publishDir` needs
  `docs.commands.preview`.

## The port and host

`start` and `preview` pick the port and the host in this order:

1. `--port` and `--host`.
2. The `url:` of a declared [collection](/manni/meta/reference/configuration/#collections),
   when its host is `localhost`, `127.0.0.1` or `[::1]`.
3. The framework's default. manni passes no port or host flag then, so the
   framework's own default stands.

The `url:` is the one `manni a11y check` seeds its crawl from, so the served
site and the crawl agree. When several collections name different local host
and port pairs, manni warns and uses the framework's default. Neither flag
applies to a command set in `docs.commands`, and passing one is refused.

## The built-in server

MkDocs, Zensical, Sphinx, Hugo and Jekyll have no preview server of their own.
For those, `preview` serves the build output with a small static server inside
manni.

- It binds `127.0.0.1`, or the host chosen above.
- It mounts the output at the collection `url:` path when there is one, so a
  site built under `/manni/` answers there.
- It serves `index.html` for a directory, and `404.html` for a missing path
  when the output has one.
- It prints its URL to stdout, as `http://127.0.0.1:8000/`.

## Configuration

Every key under `docs:` is optional. This repository's own config has no
`docs:` section, because detection finds Starlight in `docs/`.

```yaml title="manni.config.yaml"
docs:
  # The site's directory, relative to this file.
  dir: docs
  # Whole command lines, run through the shell in `dir`.
  commands:
    start: pnpm dev --port 4000
    build: pnpm build
    preview: npx serve dist -l 4000
```

| Key | Type | Default | Description |
|---|---|---|---|
| `docs.dir` | string | detected | The site's directory, resolved against the config file. |
| `docs.commands.start` | string | detected | Replaces the dev-server command. |
| `docs.commands.build` | string | detected | Replaces the build command. `preview` runs it too. |
| `docs.commands.preview` | string | detected | Replaces the serve step of `preview`. The build still runs first. |

A set command replaces the detected one for its verb, and the others stay
detected. When every command a verb needs is set, detection is skipped. So a
framework the table does not list works through config alone, and `dir` then
defaults to the config file's directory. Any other key under `docs:` is
refused, exit `2`.

## Messages and exit codes

Every diagnostic goes to stderr, prefixed `manni:`. Stdout carries the
framework's own output and the built-in server's URL.

| When | Line | Exit |
|---|---|---|
| Before a detected command runs | `manni: Starlight in docs/. Running npm run dev -- --host 127.0.0.1 --port 4321` | n/a |
| Before a configured command runs | `manni: Running docs.commands.start in docs/: pnpm dev --port 4000` | n/a |
| The built-in server is listening (stdout) | `http://127.0.0.1:8000/` | n/a |
| Ctrl-C or SIGTERM stops a server, or `preview` during its build | nothing | `0` |
| A build succeeded | the framework's output | `0` |
| Local collection URLs disagree (a warning) | `manni: collections site and api name different local URLs. Using Starlight's default port; pass --port to pick one.` | n/a |
| No site found | `manni: no docs site found in ./, docs/, website/ or site/. Pass the site's directory, or set docs.commands.start in manni.config.yaml.` | `2` |
| `[dir]` has no marker | `manni: no docs framework detected in website/. Set docs.commands.build in manni.config.yaml.` | `2` |
| Two frameworks in one directory | `manni: docs/ holds more than one docs site: Docusaurus (@docusaurus/core), MkDocs (mkdocs.yml). Set docs.commands.start in manni.config.yaml.` | `2` |
| No local build (Mintlify, Fern) | `manni: Mintlify has no local build. Run manni docs start, or set docs.commands.build.` | `2` |
| The binary is not installed | `manni: mint not found on PATH. Install Mintlify's CLI, or set docs.commands.start.` | `2` |
| Node dependencies are not installed | `manni: astro is not installed for docs/. Run npm ci in docs/ first.` | `2` |
| The command failed | `manni: npm run build exited with code 1.` | `2` |
| The port is taken (built-in server) | `manni: port 8000 is in use. Pass --port, or stop the process holding it.` | `2` |
| A bad `--port` | `manni: --port must be an integer from 1 to 65535, got "abc".` | `2` |
| `--port` with a configured command | `manni: --port does not apply to docs.commands.start. Put the port in that command.` | `2` |
| `--host` with a configured command | `manni: --host does not apply to docs.commands.start. Put the host in that command.` | `2` |
| `--host` on Mintlify or Fern | `manni: Mintlify's dev server takes no host option. Drop --host.` | `2` |
| `preview` on Mintlify or Fern, with only `docs.commands.build` set | `manni: Mintlify has no local preview. Run manni docs start, or set docs.commands.preview.` | `2` |
| Arguments after `--` for the built-in server | `manni: MkDocs previews through manni's built-in server, which takes no extra arguments. Drop the arguments after --.` | `2` |
| A `-c` file that does not exist | `manni: Config file not found: "ci/manni.config.yaml".` | `2` |
| `[dir]` does not exist | `manni: website/ does not exist.` | `2` |
| An unknown config key | ``manni.config.yaml: `docs:` has unknown key "framework". Supported keys: dir, commands.`` | `2` |
| A config value of the wrong type | `manni.config.yaml: docs.commands.start must be a string.` | `2` |

A hint that names `docs.commands.<verb>` names the verb that ran. The current
directory shows as `./`, as in `Starlight in ./.` for a site at the root. Two
Node frameworks in one directory are named by their package, in table order.
The missing-dependencies hint names the install command of the package
manager. That is `npm ci` when an npm lockfile exists, else `npm install`,
`pnpm install`, `yarn install` or `bun install`. Exit `1` is
never used, because nothing here is a finding. A failed build is an
operational error, and the framework has already printed why.

| Code | Meaning |
|---|---|
| `0` | The build succeeded, or a signal stopped the server. |
| `2` | Nothing to run, a usage error, or the command manni ran failed. |

## Examples

In this repository unless noted.

```text
# The dev server, on the port the collection url: names
$ manni docs start
manni: Starlight in docs/. Running npm run dev -- --host 127.0.0.1 --port 4321

# A production build only
$ manni docs build
manni: Starlight in docs/. Running npm run build

# Build, then serve; a11y check in another terminal needs no flags
$ manni docs preview
manni: Starlight in docs/. Running npm run build
manni: Starlight in docs/. Running npm run preview -- --host 127.0.0.1 --port 4321

# A directory named, and a port chosen (a Docusaurus repository)
$ manni docs start website --port 3001
manni: Docusaurus in website/. Running npm run start -- --port 3001

# The built-in server (an MkDocs repository with uv)
$ manni docs preview
manni: MkDocs in docs/. Running uv run mkdocs build
http://127.0.0.1:8000/

# A configured command (docs.commands.start: pnpm dev --port 4000)
$ manni docs start
manni: Running docs.commands.start in docs/: pnpm dev --port 4000

# Everything at once
$ manni docs preview docs -c ci/manni.config.yaml --host 0.0.0.0 --port 4000 -- --open
manni: Starlight in docs/. Running npm run build
manni: Starlight in docs/. Running npm run preview -- --host 0.0.0.0 --port 4000 --open
```

In CI, start `preview` in the background and wait for the port before the
crawl. A server started with `&` returns at once, and the build runs first:

```yaml
- run: npx @hawkeyexl/manni docs preview > preview.log 2>&1 &
- run: until curl -fsS http://127.0.0.1:4321/manni/ > /dev/null; do sleep 1; done
- run: npx @hawkeyexl/manni a11y check -f github
```
