A docs plan names its readers and the jobs they come to do. Then the plan sits
in a slide deck, and the pages drift away from it. A page claims a persona
nobody keeps, and a journey ends up with no page at all. **Strategy records**
keep the plan as pages beside the docs, and `manni strategy check` holds every
page to them. This step builds on the term you defined in the step before.

## Write the records

One record per audience, persona and journey. Each is a page whose `type:`
says which it is:

```md title="strategy/integrators.md"
---
type: audience
id: integrators
title: Integrators
description: Developers who call the widget service from their own code.
---
```

```md title="strategy/sam.md"
---
type: persona
id: sam
title: Sam, script author
description: Sam automates a nightly report and sends jobs from a script.
audience: integrators
---
```

```md title="strategy/first-job.md"
---
type: journey
id: first-job
title: Send a first job
description: Sam runs a first job and reads its result.
personas: [sam]
---
```

Give them a collection, and hold them to the core schema alone. They are
records, not guides, so the guides' doctypes do not apply:

```yaml title="manni.config.yaml"
collections:
  # …guides and glossary, unchanged…
  - name: strategy
    paths:
      - "strategy/*.md"

meta:
  overrides:
    # …the guides override, unchanged…
    - collection: strategy
      schemas:
        - manni:core:1.0.0
```

## Check the pages against them

```sh
manni strategy check
```

```text
strategy/first-job.md:3
  warning manni:strategy/unserved-journey     no page names this journey in journeys:.
                                              Name it on the pages that serve it.
                                              manni:strategy unserved-journey: No page names the journey in journeys:. Records do not count, and a draft or archived journey is exempt.
                                              Guide: https://hawkeyexl.github.io/manni/strategy/reference/rules/#unserved-journey

1 warning in 3 records
```

The journey exists, and no page serves it. `docs/run-a-job.md` does. Name the
audience in its frontmatter:

```yaml title="docs/run-a-job.md"
audiences: [integrators]
```

The persona and the journey go in the page's sidecar, because the built-in
audience vocabulary keeps them off the published page:

```yaml title="docs/run-a-job.meta.yaml"
docs/run-a-job.md:
  personas: [sam]
  journeys: [first-job]
```

Run `manni strategy check` again:

```text
✓ 3 records, 5 references, no findings
```

The [strategy section](/manni/strategy/) covers journey steps, and sharing one
set of records across repositories.
