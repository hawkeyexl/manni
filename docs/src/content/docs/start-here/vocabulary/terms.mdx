One page calls a thing a *job*, and the next calls it a *task*. Search
splits the idea in two, and a translator renders it twice. A **term** is a page
that defines one name. Pages name the terms they use in `concepts:`, and
`manni term check` holds both sides to each other. This track starts from the
trunk's end state.

## Define a term

A term page says `type: term`, and gives a `label` and a `definition`:

```md title="glossary/job.md"
---
title: Job
description: The glossary entry for a job.
type: term
id: job
label: job
definition: A unit of work the widget CLI sends to the widget service.
---
```

The guides' schema allows only three doctypes, so the glossary gets a
collection of its own:

```yaml title="manni.config.yaml"
collections:
  # …the guides collection, unchanged…
  - name: glossary
    paths:
      - "glossary/*.md"
```

## Check the terms

```sh
manni term check
```

```text
glossary/job.md:1
  notice manni:term/unused-term          no page's concepts: names this term.
                                         Name it in the concepts: of a page that uses it.
                                         manni:term unused-term: No page's concepts: names the entry, or an entry in another language with its id.
                                         Guide: https://hawkeyexl.github.io/manni/term/reference/rules/#unused-term

1 notice in 1 term
```

A notice never fails the check, and it says what to do. Name the term on the
page that introduces it, in the frontmatter of `docs/index.md`:

```yaml title="docs/index.md"
concepts: [job]
```

Run `manni term check` again:

```text
✓ 1 term, 1 reference, no findings
```

A `concepts:` value that no term defines is an error, so a misspelled or
retired name fails the check. The [term section](/manni/term/get-started/) covers
broader and narrower terms, and writing the glossary out for Vale.
