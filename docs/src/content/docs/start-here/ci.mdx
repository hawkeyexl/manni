Every track left a check behind, and a check nobody runs on a pull request
stops catching anything. One CI step per tool works until someone sets up a
new track and forgets the pipeline. `manni check` runs every check the
repository has set up, and skips the rest. Setting up a track is what puts it
in the gate. This is where every track joins.

## Run it

```sh
manni check
```

On the trunk's end state, with no track taken, the run ends:

```text
Suites
  default: 0/0 passed — 100% vs target 100% ok (23 skipped)

skipped  cite check       no page carries citations
skipped  lint check       no lint: section
skipped  term check       no terms in any collection
skipped  strategy check   no strategy records in any collection
skipped  graph check      no graph: section

7 checks over 4 files: 0 failed, 5 skipped
```

Each check prints its own report first. Here those are `meta validate` and
`docevals run`, which `check` runs with `--deterministic-only`, so no model is
called. A skipped line says why that check did not run, so you can see what
the gate does not cover. Take a track, and its check leaves the skipped list.
After the Vocabulary track, the same command ends:

```text
graph check
0 errors, 0 warnings, 0 notices

skipped  cite check   no page carries citations
skipped  lint check   no lint: section

7 checks over 8 files: 0 failed, 2 skipped
```

`check` exits `0` when clean, `1` on an error in a check that ran, and `2`
when manni itself cannot run.

## Put it in CI

On GitHub Actions, the manni Action runs `manni check` when it is given no
inputs. Each finding becomes an annotation on the line that caused it:

```yaml title=".github/workflows/docs.yml"
on: pull_request

jobs:
  manni:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
        with:
          fetch-depth: 0   # cite check reads the commit each pin was minted at

      - uses: hawkeyexl/manni@v4
```

`check` never runs `a11y` or `test`. One needs a running site and a browser,
and the other runs the pages' shell steps. Give each its own step if you took
the Published site track. [Gate every check](/manni/family/check/) covers the
other output formats and a run without the Action.

## See what is in play

```sh
manni status
```

```text
manni 4.28.0   config manni.config.yaml   collection guides (4 files)

meta       in play       meta: section
cite       not set up    no page carries citations
                         Pin a sentence to its source with manni cite add.
lint       not set up    no lint: section
                         Add a lint: section. manni lint templates lists the templates it can apply.
docevals   in play       4 pages declare evals
term       not set up    no terms in any collection
                         Add a page with type: term to a collection.
strategy   not set up    no strategy records in any collection
                         Add a page with type: journey to a collection.
graph      not set up    no graph: section
                         Run manni graph init to add a starter graph: section.
a11y       not checked   needs a running site and a browser
                         Run manni site preview, then manni a11y check.
test       not checked   runs the pages' shell steps and synthetic users
                         Run manni test procedures or manni test tasks.
tracevals  not checked   judges recorded sessions with a model
                         Run manni tracevals run over sessions, or add tracevals.runtime to judge each turn.
```

Every *in play* row is a check `manni check` runs. The status shown is the
trunk's, before any track.
