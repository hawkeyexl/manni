A schema checks what a page says about itself. It cannot see that a concept
page has no use cases, or that a how-to has lost its steps. Only a reviewer's
memory catches that, until a **template** says what each doctype must hold.
This track starts from the trunk's end state.

## Turn lint on

Each sample page already declares its doctype in `type:`, and lint ships a
built-in template for each one. Add an empty `lint:` section, and lint holds
every page to its template:

```yaml title="manni.config.yaml"
lint: {}
```

```sh
manni lint check
```

```text
Checked: structure.
Using manni.config.yaml (.)
✓ docs/index.md
✓ docs/reference/cli.md
✓ docs/run-a-job.md
✗ docs/timeouts.md
    14:1  manni:lint/structure/missing-section  Timeouts and retries: Missing section "Use cases"
          tgdp:concept:1.6 use-cases: Show how the concept helps the reader, starting from a real problem they face and how the concept solves it.
          Guide: https://gitlab.com/tgdp/templates/-/blob/v1.6.0/concept/guide_concept.md

4 files checked, 3 passed, 1 failed, 0 skipped
```

`docs/timeouts.md` passed the schema, and lint fails it, exit `1`. A concept
page says what the concept is for, and this one does not. Add the section:

```md title="docs/timeouts.md"
## Use cases

Raise the timeout for a job that runs for minutes.
```

Run `manni lint check` again, and every page passes:

```text
Checked: structure.
Using manni.config.yaml (.)
✓ docs/index.md
✓ docs/reference/cli.md
✓ docs/run-a-job.md
✓ docs/timeouts.md

4 files checked, 4 passed, 0 failed, 0 skipped
```

The [lint section](/manni/lint/get-started/) covers reading a finding and
writing your own templates.
