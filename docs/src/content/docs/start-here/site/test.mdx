A procedure reads fine long after the command it documents has changed. The
first person to find out is a reader who followed it and got something else.
A **procedure test** runs the procedure's own commands and checks what they
print. `manni test procedures` runs the tests with
[Doc Detective](https://doc-detective.com/), and reports a failure at the page
and line that broke. This step closes the Published site track. Its test runs
commands rather than the built pages, so it needs no preview running.

## Write the test into the page

The sample's `docs/run-a-job.md` tells the reader to run a job and expect
`Job hello: done`. Say the same thing as a test, in comments at the end of the
page:

{/* test ignore start */}

```md title="docs/run-a-job.md"
<!-- test {"testId":"run-a-job"} -->
<!-- step {"runShell":{"command":"node src/widget.mjs run hello","stdio":"Job hello: done"}} -->
<!-- test end -->
```

{/* test ignore end */}

The comments do not render, so readers never see them.

## Run it

Doc Detective has to be on your `PATH`. Install it with
`npm install -g doc-detective`.

```sh
manni test procedures docs/run-a-job.md
```

```text
1 test: 1 passed, 0 failed, 0 warnings, 0 skipped
```

Now change the CLI so it prints `Job hello: queued`, and run it again. The
procedure on the page is wrong now, and the test says where:

```text
docs/run-a-job.md
  32  FAIL     Returned exit code 0. Couldn't find expected output (Job hello: done) in stdio (stdout or stderr). Fix the step, fix the procedure it documents, or report a product regression.
               Doc Detective runShell
               Guide: https://docs.doc-detective.com/docs/actions/runshell

1 test: 0 passed, 1 failed, 0 warnings, 0 skipped
```

The exit code is `1`. The [test section](/manni/test/) covers the CI step,
and having a synthetic user attempt a task with `manni test tasks`.

Like `a11y`, `test` stays *not checked*. A hook never runs a page's shell
steps, so `manni check` leaves them alone. Run `manni test procedures` as its
own CI step.
