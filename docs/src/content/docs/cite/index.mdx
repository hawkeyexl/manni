A citation has two ends, and both are pinned the same way. The **claim** is
the page lines the sentence occupies, and a hash of them. The **source** is
the file, the lines it rests on, a hash of those, and the commit they were
read at. manni cite checks both ends and tells you which sentence stopped
being true, not which page to re-read.

{/* cite clean-run-one-hash */}
{/* cite gained-neighbours-moved */}
{/* cite moved-one-command */}
{/* cite changed-with-commits */}
It runs from git alone. No model, no network, one hash per end on a clean run.
A line that gained neighbours above it is moved, and one command fixes that. A
line whose bytes changed is changed, with the commits since, and a person
decides whether the prose or the pin is wrong. Nothing on the page repeats the
sentence. Under claim lines, a copy edit on a line beside it raises nothing.
Under a marker, an edit anywhere in the anchored paragraph is a
`claim-changed` warning by default.

## Three commands

| Command | Does |
| --- | --- |
| `manni cite add <page>:L <src>:L` | Mints a citation over the page lines and the source range, and writes the entry to the page's frontmatter or to a sidecar manifest. |
| `manni cite check [paths...]` | Classifies each end of every citation, and reports the findings through the same formats manni meta uses. |
| `manni cite update [paths...]` | Rewrites moved ends in place, on either side. With `--accept`, re-pins changed ones. |

## A 30-second proof

You don't need to install anything. Say `docs/limits.md` says on line 9 that
the fetch timeout is 10 seconds, and that sentence rests on line 2 of
`lib/limits.ts`. The page already has frontmatter. Pin both ends:

```sh
npx @hawkeyexl/manni cite add docs/limits.md:9 lib/limits.ts:2 --id fetch-timeout
```

```
docs/limits.md: added fetch-timeout to frontmatter (claim at line 19, sha256-c41f09aa…; source lib/limits.ts:2, sha256-78af1d33…, 9265563)
```

{/* cite stored-claim-body-lines */}
The entry pushed the sentence down the file, and the stored claim line did not
move: it counts the body, not the file. Check it:

```sh
npx @hawkeyexl/manni cite check docs/limits.md
```

```
✓ docs/limits.md
    ✓ fetch-timeout   :19 current   lib/limits.ts:2 current

1 file checked, 1 passed, 0 failed, 0 findings
```

Then someone raises the timeout to 30 seconds and commits. The page has not
changed, so metadata validation still passes. The citation check does not:

```
✗ docs/limits.md
    ✗ fetch-timeout   :19 current   lib/limits.ts:2 changed since 9265563, 1 commit

1 file checked, 0 passed, 1 failed, 1 finding
```

{/* cite finding-on-sentence */}
{/* cite finding-on-sentence-anchor */}
{/* cite exit-one-on-error */}
The finding is annotated on line 19, the sentence. The exit code is `1`, so CI
goes red on the line that needs a person, and nowhere else. That's the whole
loop: pin, check, read the finding, fix the sentence, re-pin.

## What manni cite checks, and what it doesn't

<CardGrid>
  <Card title="It checks" icon="approve-check">
    That the lines a sentence cites are still the bytes they were when the
    citation was written, and that the sentence itself is. Where either end
    went if it moved. What changed and in which commits if the source did not
    survive. That every marker names a real entry, and every entry has one
    anchor.
  </Card>
  <Card title="It doesn't" icon="close">
    Judge whether the sentence was ever right, read the source for meaning, call
    a model, or reach the network. A `source-changed` finding is a question for
    a person; the check only makes sure it is asked about one sentence rather
    than a whole page.
  </Card>
</CardGrid>

Citations are written in the `manni:citations` vocabulary. Its draft is open
for review with the family's other vocabularies, and manni cite
bundles it. It is not a built-in schema of manni meta. With the schema file in
its set, `manni meta validate` checks that an entry is well-formed; only `manni cite check` can say whether it still holds. Both
tools ship in one package and read one `manni.config.yaml`, under their own
keys.
