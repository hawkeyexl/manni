The citation tool reads two keys of the family's one config file,
`manni.config.yaml`. The top-level `collections:` list says which pages exist,
and the `cite:` section holds the tool's own settings. Together they let CI
run a bare `manni cite check`. The config is optional. Every key has a default. The tool runs without a
config when two things hold. You pass paths on the command line, and the
sources sit in the same repository as the pages.

```yaml title="manni.config.yaml"
collections:
  - name: docs-pages
    paths: ["docs/**/*.md"]      # the document set, read by every tool
meta:
  schemas: ["./page.schema.json"] # the metadata tool's section; cite never reads it
cite:
  baseline: .manni-cite-baseline.json
```

## Document sets

The pages a bare `manni cite check` or `manni cite update` covers come from
the top-level `collections:` list, declared once for every tool. Each
collection names its `paths` and `exclude` globs, relative to the config
file. The keys, their rules and the `--collection` flag that narrows a run to
one are on the metadata tool's
[configuration reference](/manni/meta/reference/configuration/#collections).
A family file that declares `collections:` and no `cite:` section is still
this tool's config: the documents are declared, and every cite key takes its
default.

`paths` and `exclude` are not `cite:` keys. Each is refused with an error
that says where it went (exit 2):

```
manni.config.yaml: "paths" is no longer a cite key. Document sets are declared once for every tool, under a top-level collections: list. See https://hawkeyexl.github.io/manni/meta/reference/configuration/#collections
manni.config.yaml: "exclude" is no longer a cite key. Document sets are declared once for every tool, under a top-level collections: list. See https://hawkeyexl.github.io/manni/meta/reference/configuration/#collections
```

## Keys

| Key | Type | Default | Mirrors | Description |
|---|---|---|---|---|
| `allowEmpty` | `boolean` | `false` | `--allow-empty` | Treat an input set that resolves to zero files as success instead of an error (exit 2). |
| `respectGitignore` | `boolean` | `true` | `--no-gitignore` | Skip files `.gitignore` covers when expanding directories and globs. `--no-gitignore` overrides it for one run. |
| `root` | `string` | git root | `--root` | The directory `src:` paths resolve from, relative to the config file. It may point outside the repository, at a second checkout. `--root` overrides it for one run. |
| `baseline` | `string` | none | `--baseline` | Path to a [citation baseline](/manni/cite/reference/cli/#baselines), relative to the config file. Setting it turns on `--baseline` for every run; `--no-baseline` suppresses it for one. A bare `--write-baseline` records into this same file. |
| `git` | `boolean` | `true` | `--no-git` | Consult git. Index sources with `git ls-files`, record `HEAD` on `add`, and use history to tell `changed` from `never-true`. `--no-git` overrides it for one run. |
| `sources` | `boolean` | `true` | `--no-sources` | Read the sources. `false` runs the page-side rules only and marks every source-side status `skipped`; `update` refuses under it. `--no-sources` overrides it for one run. |
| `salt` | `string` | `""` | none | Keys obfuscated tokens and their pins, and turns obfuscation on. Once it is set, `add` writes every new citation as a `~token` with a keyed pin. Written by [`manni cite salt set`](/manni/cite/reference/cli/#cite-salt-set), replaced by [`manni cite salt rotate`](/manni/cite/reference/cli/#cite-salt-rotate). The environment variable `MANNI_CITE_SALT` wins over it; see [the salt](#the-salt). |
| `severity` | mapping | the [defaults](#severity) | none | Per-rule severity, `error`, `warning` or `off`. Only the rules named are changed. |

The section must be a YAML mapping; an empty `cite:` is the same as no keys.
The booleans must be booleans, so a quoted `"false"` is rejected rather than
read as on. A type error names the key and the type it wanted, and nothing
else.

### Unknown keys are errors

Any key outside the table above is an operational error (exit 2) naming the
key it did not recognize and listing the ones it accepts. The same rule holds
inside `severity`: a rule the tool does not have, or a level other than
`error`, `warning` and `off`, is an error naming the supported set.

A dropped `allowEmtpy:` would otherwise leave a config that reads as
configured and is not. The rule also means a config written for a newer manni
is rejected outright when it carries a key this version does not know. So pin
the version wherever the gate runs.

One former key is refused by name rather than as a typo. `obfuscate` used to
switch obfuscation on; the salt does that now, so a config that still carries
it hears what replaced it (exit 2):

```
cite.obfuscate is no longer a key. A configured salt obfuscates every source add writes; run `manni cite salt set` to configure one.
```

<Aside type="note" title="Values are never echoed">
An error about a key says which key and what type it wanted. It never quotes
the offending value, because `salt` is a secret and a CI log is where these
messages end up. A misspelled severity **level** is the one exception: a level
is not a secret, so `eror` is quoted back as the typo it is.
</Aside>

## Discovery

The tool looks for `manni.config.yaml` (then `manni.config.yml`) in the
working directory and each ancestor, stopping at the nearest `.git` boundary.
The first file found wins; ancestor files are never merged. A family file with
neither a `cite:` key nor a `collections:` list belongs to a sibling tool, and
discovery keeps looking up the tree. There is no pre-family filename for this
tool, so nothing else is read.

`-c <path>` names the file outright and must exist. `--no-config` skips
discovery and runs on the defaults alone. When a config governs the run,
`pretty` output says so on stderr; the machine formats stay clean.

### What relative paths are relative to

| Path | Relative to |
|---|---|
| a collection's `paths:` and `exclude:` | the config file's directory |
| `root:` and `baseline:` | the config file's directory |
| positional `[paths...]` | the working directory |
| `--root` and `--baseline <path>` | the working directory |

So `cd docs && manni cite check` reaches the same files, the same root and the
same baseline as a run from the repository root. Baseline fingerprints match
whichever directory the command ran from.

## The salt

The salt keys every obfuscated token and every keyed pin, and it is the
switch that turns obfuscation on. Once a salt is configured, `add` writes
every source as a `~token` with a keyed pin, and there is no flag to remember.
It comes from three places, in this order:

1. The environment variable `MANNI_CITE_SALT`, when set.
2. `cite.salt` in the config.
3. The empty string, which is no salt at all.

The environment wins so that a CI secret can key a private checkout while the
public config file carries no salt at all. A config `salt:` is for a private
repository whose config is itself private. With the empty string, a guessable
path is brute-forceable: sixteen hex digits of `sha256("\n" + path)` is a
cheap oracle for anyone who can guess `lib/limits.ts`. A public page that
cites a private source wants a real salt behind it. `--obfuscate` on `add`
still forces a token under the empty string, and that is the weak form.

### Setting it

[`manni cite salt set`](/manni/cite/reference/cli/#cite-salt-set) writes the
key into the discovered config, or the one `-c` names. Given no value, it
generates 32 lowercase hex characters. It keeps the file's comments
and other keys, creates the `cite:` section when there is none, and never
prints the value. It refuses when a salt is already there, because replacing
one in place is what `rotate` is for.

```sh
manni cite salt set
```

```
Salt written to manni.config.yaml.
```

Keep the config private once it carries a salt, or leave the key unset and
put the salt in `MANNI_CITE_SALT` instead. A salt in the environment
obfuscates every `add` exactly as a configured one does.

### Rotating it

A token or a pin minted under one salt does not resolve under another. Change
the key by hand and every obfuscated citation reads as `missing`.
[`manni cite salt rotate`](/manni/cite/reference/cli/#cite-salt-rotate) is
the way to change it. It re-keys every obfuscated citation in the given
pages under the new salt, then writes that salt where the old one lives.
Nothing is written unless every citation re-keyed, so the corpus is never
half under each salt.

A salt in the config is replaced in the config:

```sh
manni cite salt rotate --root ../code
```

```
Salt written to manni.config.yaml.
```

A salt in `MANNI_CITE_SALT` rotates through the environment. The tool cannot
update a secret, so `--to` is required and the config is never touched. Pass
the new value, then update the secret to it:

```sh
MANNI_CITE_SALT="$OLD_SALT" manni cite salt rotate --to "$NEW_SALT" --root ../code
```

```
Salt not written: it comes from MANNI_CITE_SALT. Update the secret to the value you passed.
```

Without `--to`, the run refuses (exit 2) before it reads a page:

```
manni: The salt comes from MANNI_CITE_SALT; pass --to <value>, re-key with it, then update the secret. Nothing is written to config.
```

The rule keeps a secret out of a public file. In the two-repository layout
the config is committed to the public docs repository, and a rotation that
wrote there would publish the new salt. `set` still warns when
`MANNI_CITE_SALT` is set, because the environment wins over the key it
wrote. See [public docs, private code](/manni/cite/set-up/public-docs-private-code/).

## Example

The two-checkout layout, which is the reason `root`, `sources` and the salt
exist. The pages are in the public docs repository, so SARIF locations
resolve. The sources are reached through `--root` from a private CI job that
checks out both. The file is public, so it carries no `salt:`. The salt lives
in `MANNI_CITE_SALT`, and a salt in the environment obfuscates every `add`
exactly as a configured one would:

```yaml title="manni.config.yaml (public docs repository)"
collections:
  - name: site
    paths: ["src/content/docs/**/*.{md,mdx}"]
cite:
  severity:
    moved: error          # this repo wants a moved pin to block, not warn
```

```sh
# Public CI, no access to the code: page-side rules only, exit 0 on a clean page.
manni cite check --no-sources

# Private CI: docs and code checked out side by side; from the docs checkout.
MANNI_CITE_SALT="$CITE_SALT" manni cite check --root ../code -f sarif > cite.sarif
```

A single-repository setup needs none of that:

```yaml title="manni.config.yaml (pages and sources in one repository)"
collections:
  - name: docs-pages
    paths: ["docs/**/*.md"]
cite:
  baseline: .manni-cite-baseline.json
```

## Severity

Every rule has a default severity, and `severity:` moves any of them. `error`
counts toward exit 1, `warning` is reported and never moves the exit code, and
`off` is not reported at all. The rules themselves are defined on the
[citations reference](/manni/cite/reference/citations/#statuses-and-rules).

| Rule | Default | Why |
|---|---|---|
| `current` | `off` | Not a finding. `pretty` still lists the citation as `✓`. |
| `moved` | `warning` | `update` fixes it mechanically, and a PR job that failed on a two-line insert above a cited line would make the ratchet noisy. |
| `claim-ambiguous` | `warning` | The claim was found; the tool only cannot say which occurrence. |
| `moved-ambiguous` | `error` | Two or more copies of the cited lines; the tool will not guess. |
| `changed` | `error` | The lines the sentence rests on are gone from where they were. |
| `missing` | `error` | The path is not a tracked file under the root, or the token resolves to nothing. |
| `never-true` | `error` | The pin did not match even at the commit it claims to have been minted at. |
| `claim-missing` | `error` | The sentence is not in the body. |
| `statement-orphan` | `error` | An inline reference names an id no frontmatter entry has. |
| `statement-invalid` | `error` | A statement the tool cannot read, or one that its format does not allow. |
| `entry-invalid` | `error` | A frontmatter entry the schema refuses, or a duplicate id. |
| `quote-drift` | `error` | The fenced block does not reproduce the cited lines. |

```yaml title="manni.config.yaml"
cite:
  severity:
    moved: error        # a moved pin blocks until update runs
    claim-ambiguous: off
```

A rule set to `off` produces no finding in any format and never enters a
baseline. A rule set to `warning` renders as `↕` in `pretty`, `::warning` in
`github`, `level: warning` in SARIF, and a passing testcase in JUnit, exactly
as the metadata tool's
[severity](/manni/meta/reference/output-and-exit-codes/#severity) does.
