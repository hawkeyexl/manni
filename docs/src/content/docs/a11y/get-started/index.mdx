This page takes a site you can serve locally and makes it pass its own
accessibility check. You install a browser once, crawl the build, read the score
and the findings, and fix them. The last run on this page exits `0`. It is the
same command a [CI job](/manni/a11y/ci/) runs against the deployed site.

<Aside type="note" title="Where this output came from">
Every output block below was copied from a real run. The site is
`test/fixtures/a11y/site/`, the three-page fixture the test suite uses, served
on port 4173. A crawl needs a browser and a running server, and the
docs-as-tests job has neither. So the commands here are not replayed by CI the
way the `manni meta` examples are. Long axe failure summaries are cut with `…`.
</Aside>

## Before you start

{/* cite node-24-or-newer */}
`manni a11y check` runs on [Node.js](https://nodejs.org/) 24 or newer. Check
your version:

```sh
node --version
```

You also need a browser and a served site. The next two sections cover both.

## Install a browser

{/* cite browser-not-bundled */}
axe runs inside a real browser. Installing `@hawkeyexl/manni` does not download
one, so that the metadata tool stays a small install. `manni a11y check` looks
for Google Chrome, then Microsoft Edge, then Playwright's own Chromium. If you
have neither Chrome nor Edge, install the Chromium once:

```sh
npx playwright install chromium
```

{/* cite no-browser-message */}
Without any of the three the command stops before it loads a page:

```
manni: No browser found. Install one with `npx playwright install chromium`, or install Google Chrome or Microsoft Edge.
```

{/* cite no-browser-exit-2 */}
That is exit `2`, an operational error rather than a failed check. You do this
once per machine. GitHub-hosted runners already ship Chrome, so the CI step
usually needs nothing beyond the package.

## Serve the build

{/* cite url-not-directory */}
The check reads a URL, never a directory. Build the site, then serve the output
on a port of your choice:

```sh
npm run build
npx serve dist -l 4173
```

Leave that running and open a second terminal for the rest of this page. Any
static server will do. The port only has to match the URL you check.

<Aside type="tip" title="Checking a deployed site instead">
Point the command at the public URL and skip the build and the server. The
crawl is the same. Checking the local build is what catches a finding before a
reader meets it.
</Aside>

Two pages carry findings, so the command exits `1`. On a terminal, a status
line on stderr names the page the crawl is on and clears before the report
prints. Progress never writes to stdout, so `-f json` piped into another tool
still gets clean output.

## Read the report

Four things are on screen, from the top down.

| Part | What it tells you |
|---|---|
| The header | How many pages were checked, and where they came from. A sitemap supplied them here. Without one it reads `(no sitemap; followed links)`. |
| The page line | `✓` or `✗`, the URL, the [score](/manni/a11y/#what-the-score-means), and the remaining findings by severity. The glyph carries the meaning, so the line survives a greyscale screenshot. |
| The violation line | The severity, the axe rule id, and axe's own impact. Then the number of failing elements, axe's one-line description, and the rule's page on Deque University. |
| The node line | One failing element, as a CSS selector and axe's statement of what is wrong with it. The first three elements per rule print. |

{/* cite score-share-of-rules */}
The score is the share of axe rules that applied to the page and passed.
Violations below the severity floor do not count against it. Nothing
is weighted, so it is not a Lighthouse score. Read the score as a trend and the
exit code as the verdict. A page with one error scores `94` and still fails the
run.

## Fix the first finding

Start with the cheapest one. `html-has-lang` fired on `about.html`, and the node
line names the element as `html`. The page declares no document language, which
affects every screen reader that reads it aloud. That is one attribute in the
template:

```html title="about.html" del={2} ins={3}
<!doctype html>
<html>
<html lang="en">
  <head>
```

Rebuild, then run the crawl again:


## Work one page at a time

A full crawl of a large site takes a minute or more, which is slow to iterate
against. While you are fixing one page, check that page alone:

```sh
npx @hawkeyexl/manni a11y check http://127.0.0.1:4173/orphan.html --no-crawl
```

{/* cite no-crawl-skips-sitemap */}
`--no-crawl` skips the sitemap lookup and the link following, and checks exactly
the URLs you name. After alt text is added to the image on that page:

```
Checked 1 of 1 pages (no crawl)
✓ http://127.0.0.1:4173/orphan.html  score 100

0 violations on 0 of 1 pages
```

{/* cite single-page-exit-0 */}
Exit `0`. [Fix a failing check](/manni/a11y/fix/) walks one violation end to
end, including how to choose the words in an alt attribute.

## Re-run until it is clean

With the button given a label, the paragraph given a readable colour, and both
images given alt text, the whole crawl comes back green:

```
Checked 3 of 3 pages (sitemap: http://127.0.0.1:4173/sitemap.xml)
✓ http://127.0.0.1:4173/  score 100
✓ http://127.0.0.1:4173/about.html  score 100
✓ http://127.0.0.1:4173/orphan.html  score 100

0 violations on 0 of 3 pages
```

{/* cite clean-crawl-exit-0 */}
That is exit `0`, and it is what a CI gate waits for.

## Put the seeds in config

{/* cite config-urls-no-args */}
Once the URL lives in `manni.config.yaml`, the command takes no arguments. That
is the form a CI step runs, and the file is the one `manni meta` already reads:

```yaml title="manni.config.yaml"
a11y:
  urls: ["https://docs.example.com/"]
  severity: error
```

```sh
npx @hawkeyexl/manni a11y check
```

{/* cite severity-floor */}
`severity` is the floor. At `error` the warnings and notices are dropped before
the score and the exit code are decided. The
[configuration keys](/manni/a11y/reference/cli/#configuration) table has the
types and defaults, and [where seeds come
from](/manni/a11y/reference/cli/#where-seeds-come-from) covers seeding from a
collection instead.
