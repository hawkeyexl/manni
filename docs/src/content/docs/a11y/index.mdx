`manni a11y check` takes a URL, crawls the site behind it, and runs
[axe-core](https://github.com/dequelabs/axe-core) against every page it reaches.
{/* cite violation-shape */}
Each page gets a list of violations. Each violation carries the rule that fired,
{/* cite exit-1-on-violation */}
{/* cite exit-1-failed-count */}
the element it fired on, and axe's own statement of what to change. The run
exits `1` when any page still has a violation, so the command you run locally is
the same one that gates a pull request.

## What it checks, and what it leaves alone

It checks what axe can decide from a rendered page. That is missing alternate
text, buttons and links with no accessible name, form fields without labels,
contrast, document language, and ARIA misuse.

It does not test keyboard flows, read your source, or write anything back. There
is no `--fix`, because the check never sees the Markdown, template, or component
tree that produced the page. [Fix a failing check](/manni/a11y/fix/) covers what
it hands the person who fixes the page, and what a green run does not prove.

{/* cite no-bundled-browser */}
axe runs inside a real browser, and installing `@hawkeyexl/manni` does not
download one. [Get started](/manni/a11y/get-started/) has the one-time install.

## How the crawl works

{/* cite same-host-scope */}
{/* cite every-seed-host-in-scope */}
The crawl stays on the host of the URL you gave it. `docs.example.com` and
`example.com` are different hosts, and so is `www.example.com`; `http://` and
`https://` of one host are the same site. Give several seeds and links are
followed on every seed's host. Sitemap URLs stay on the first seed's host,
because one sitemap is read per run, from the first seed, as
[proposal 0035](https://github.com/hawkeyexl/manni/blob/main/docs/proposals/0035-a11y-domain.md#1-why-one-sitemap-from-the-first-seed) records.

Pages come from two places, in this order:

1. **The sitemap.** The site's own list of pages, when it publishes one. It
   is looked up once per run, before the browser starts. See
   [Sitemaps](#sitemaps) for when it is read, how it is found, and what
   happens without one.
2. **Links.** Every page that loads contributes the same-host `<a href>` links
   in its rendered DOM. `mailto:`, `tel:`, and links to assets such as PDFs,
   images, and stylesheets are skipped. A link's fragment is dropped, so an
   in-page anchor resolves to the page it sits on, which is already queued.

{/* cite one-at-a-time */}
Pages are checked one at a time, in the order they were discovered. Each URL is
{/* cite checked-once-dedupe */}
checked once regardless of fragment, host casing, or a trailing slash. A page
{/* cite redirect-counts-checked */}
the browser reached by redirect counts as checked too. There is no cap by
{/* cite max-pages-cap */}
{/* cite no-cap-default */}
default, and the run goes on until nothing is queued. `--max-pages <n>` bounds
{/* cite max-pages-skipped */}
it, and anything still queued at the cap is reported as `skipped`, not failed.
{/* cite no-crawl-no-sitemap */}
{/* cite no-crawl-no-links */}
`--no-crawl` checks exactly the URLs you named, with no sitemap lookup and no
link following.

{/* cite seed-load-exit-2-code */}
{/* cite seed-load-rethrows */}
A seed that does not load is exit `2`, because nothing was checked. A crawled
{/* cite crawled-page-fails-run */}
{/* cite crawled-page-error-continues */}
page that does not load is recorded against that page and the crawl continues;
the page counts as failed, so the run exits `1`.

## Sitemaps

### When it is looked up

{/* cite sitemap-first-seed */}
Once per run, before the browser starts, and only when crawling. The lookup
{/* cite sitemap-no-crawl-skips */}
uses the first seed's origin and path. `--no-crawl` skips it and checks exactly
the URLs you named.

### How it is found

{/* cite sitemap-fetch-timeout */}
Plain HTTP requests, no browser, each with a 10-second timeout. Candidates are
{/* cite sitemap-first-valid-wins */}
tried in this order, and the first that answers 2xx and parses as a sitemap
wins:

1. `robots.txt` at the origin, and every `Sitemap:` line in it, in order.
2. Walking from the seed's own directory up to the site root, nearest first,
   the files `sitemap.xml`, `sitemap-index.xml`, and `sitemap_index.xml` in
   each directory.

{/* cite sitemap-walk-example */}
For `https://h/manni/meta/fix/` the walk asks `/manni/meta/fix/`, then
`/manni/meta/`, then `/manni/`, then `/`. The walk exists for project sites
published under a path. `https://hawkeyexl.github.io/manni/` serves
`/manni/sitemap-index.xml` and nothing at the origin. A body that is 2xx but
{/* cite sitemap-non-xml-skipped */}
not sitemap XML is skipped, and the next candidate is tried.

### When one is there

{/* cite sitemap-index-limits */}
{/* cite sitemap-index-recursion */}
A `<sitemapindex>` is followed into its child sitemaps, up to three levels deep
{/* cite sitemap-loc-filter */}
and fifty children in total. Every `<loc>` is kept when it is on the seed's
host and looks like a page. That means `http` or `https`, and not an asset such
{/* cite sitemap-joins-after-seeds */}
{/* cite sitemap-dedupe-seeds */}
as a PDF, an image, or a stylesheet. Those URLs join the queue right after the
seeds, deduped against them with a trailing slash ignored. Link following still
{/* cite links-on-top-of-sitemap */}
runs on top, so a page the sitemap missed but a checked page links to is found
{/* cite sitemap-header-line */}
too. `--max-pages` caps the whole run. The header line names the sitemap that
{/* cite sitemap-summary-field */}
was used, and `summary.sitemap` carries its URL.

### When there is none

{/* cite no-sitemap-not-an-error */}
A 404, a network error, or an unparseable body all mean "no sitemap". None of
{/* cite no-sitemap-breadth-first */}
them fails the run. The crawl falls back to same-host links from each checked
{/* cite no-sitemap-header */}
page, breadth first, and the header reads `(no sitemap; followed links)`.

### Scope

{/* cite robots-disallow-ignored */}
`Disallow` rules in `robots.txt` are not honoured. Gzipped sitemaps (`.xml.gz`)
{/* cite gzip-not-decompressed */}
are not decompressed.

## What the score means

{/* cite score-share-of-passes */}
Each page reports a score from `0` to `100`. It is the share of axe rules that
{/* cite score-after-severity-floor */}
applied to the page and passed. The `--severity` floor has already dropped the
violations you chose not to count:

```
score = round(100 × passes ÷ (passes + violations))
```

{/* cite score-unweighted */}
It is **not a Lighthouse score**. Lighthouse weights rules; this does not. A
{/* cite score-97-still-fails */}
page with one `error` and thirty passing rules scores `97`, and it still fails
the run. Read the score as a trend across pages and across runs, and
{/* cite no-score-unloaded-or-empty */}
read the exit code as the verdict. A page that did not load, or where no rule
applied, has no score.

{/* cite incomplete-not-failures */}
{/* cite incomplete-counted */}
Rules axe could not decide (its `incomplete` results, such as contrast over a
background image) are counted but never treated as failures. Only `-f json`
reports the count, as `incomplete` on each page.

## Configuration

{/* cite a11y-config-section */}
The `a11y:` key of `manni.config.yaml` sits beside `meta:` in the same file.
{/* cite flag-over-config-over-default */}
{/* cite flag-over-config-resolution */}
{/* cite config-keys-optional */}
Every key is optional; a flag on the command line wins over the same key in
config, and config wins over the default.

```yaml title="manni.config.yaml"
a11y:
  urls: ["https://docs.example.com/"]   # string[]  seeds; fallback for [urls...]
  crawl: true                            # boolean   default true
  maxPages: 500                          # integer ≥ 1; absent means no cap
  tags: ["wcag2a", "wcag2aa"]            # string[]
  severity: error                        # notice | warning | error
  timeout: 30000                         # integer ≥ 1, ms
```

{/* cite tags-restrict-rules */}
`tags` restricts axe to rules carrying any of those tags, so a gate can be
{/* cite severity-floor-filter */}
{/* cite severity-floor-compare */}
"WCAG 2.1 AA and nothing else". `severity` is the floor: findings below it are
{/* cite severity-family-values */}
dropped before the score and the exit code are decided. Its values are the
family's, `notice`, `warning`, and `error`, the same three every manni tool
{/* cite impact-to-severity-map */}
uses. axe's `critical` and `serious` both land as `error`, `moderate` as
{/* cite impact-kept */}
`warning`, and `minor` as `notice`, and each finding keeps axe's word as
`impact`. The [configuration keys](/manni/a11y/reference/cli/#configuration)
table has the types and defaults.
