One line:

Every docs framework has its own serve command, and CI files end up hand-typing it. manni docs preview detects the framework, builds, and serves on the port your config already names.

Longer:

Which command serves this docs site? Starlight wants astro preview. MkDocs wants mkdocs serve. Sphinx, Hugo, Jekyll and Docusaurus each want their own. Our CI file carried the answer by hand: a build step, then npx astro preview with a host and a port.

manni docs start, build and preview detect the framework and run its own command. Thirteen are detected, from Mintlify and Fern to MkDocs, Sphinx and Hugo. docs.commands in manni.config.yaml overrides any of them.

The port is not a second setting. It comes from the collection url: that manni a11y check already reads. So one terminal runs manni docs preview, and a bare manni a11y check in another finds the server. On this repository's own site that is 238 pages, 0 violations, exit 0.
